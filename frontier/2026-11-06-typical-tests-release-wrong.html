405 片段菜单上，典型测试放行 0.410 的隐藏错误程序

一篇预印本在 CPython、Node.js、SQLite 的 52 个受影响测试任务上，把发布门的可见输入换成典型样例、发布说明边沿输入、盲写测试。作者构造的 405 片段菜单、完整有限修复空间里，全断言门在典型输入上放行 0.410 的隐藏错误程序；作者按发布说明写的一条边沿输入把这个份额降到 0.065。假拒绝仍是 0.010，分母是隐藏正确的程序。0.410 和 0.065 是任务均值，只挂这一张菜单：大菜单是 0.278，加硬干扰后是 0.337，论文写它们不是门的属性。

10.410 到 0.065

2026 年 11 月 5 日，arXiv 收到 Accepted but Wrong: Silent Failures of LLM Code Repairs after API Migrations（arXiv:2611.08269v1，cs.SE，兼 cs.AI；作者 Xiaobo Chen、Genliang Zhu、Ziyuan Wang、Chu Wang；单位署马萨诸塞大学阿默斯特、Accentrust、佐治亚理工、杜克、伊利诺伊大学厄巴纳-香槟）。预印本，未经同行评审。abs 页 Comments 写 30 页、2 图，已预注册；工件向作者索取。本轮读的是 HTML 全文。许可是 arXiv.org perpetual non-exclusive license。

运行时升了，过程还要满足同一条义务。有的断裂会报错。有的不断：调用成功，结果变了。论文举例：枚举打成 3 而不是 Priority.HIGH；sum() 更准了，对不上账本里存的浮点；Buffer.poolSize 大了八倍，上传分块跟着变。发布门如果只拿典型测试输入，这些错修能过。

这篇只论证一个判断。判断是我的，依据是论文表 1 和正文「What makes a release gate adequate here is its inputs」（HTML）。判断是：作者构造的 405 片段菜单上，全断言门在典型输入上放行 0.410 的隐藏错误程序；作者按发布说明写的一条边沿输入把份额降到 0.065。对照面是 52 个受影响测试任务、49 个簇，任务均值。簇均值是 0.406 对 0.064，正文写两者相差不超过 0.005。假拒绝两边都是 0.010，分母是隐藏正确的程序。15 个新测试簇上是 0.471 到 0.061，那一截用来回答「这个差是不是旧池子里带出来的」，不和 0.410 进同一句倍数。主对比的 52 个任务里，55 个旧任务整份导入，重叠多少正文没按任务列出。0.410 不是 52 个任务里错了 21 个，也不是模型一次调用的失败率，更不是门换菜单之后仍成立的属性。

论文把「静默」留给变化的类别：调用成功、结果改了。把「无错」留给一次运行的结局。0.410 是 FA 全体：放行且按隐藏契约不正确。其中隐藏执行没报错的那一部分，原文定义为 error-free 的假接受，表 1 没有单列占比。

2怎么计

73 个任务覆盖 60 个有文档的变更簇：CPython 3.9.6 → 3.12.15、Node.js 20.20.2 → 24.21.0、SQLite shell 3.51.0 → 3.54.0。66 个受影响，7 个未变对照。按类：25 个静默、34 个显式、7 个无可安全修复。测试划分 52 个受影响任务、49 个簇，其中 15 个簇是新的。每个候选都在真实运行时上执行，隐藏契约不给任何模型看。

修复是在作者写好的片段菜单里选。主实验菜单 405 个片段。每个任务一条作者边沿输入，按发布说明写，质检规则要求它让未修过程在可见检查上失败。盲写器是隔离的 GPT-5.6-luna：只看见需求、钉死的摘录、输入键、典型输入及其旧输出、输出检查；看不见模板、片段、旧程序、隐藏输入。自测是修复模型自己先写输入。四种可见输入组合：只有典型（T）、加上自测（S）、加上作者边沿（E）、两边都加（ES）。

四个被接纳的模型家族：GPT-5.6-luna（Codex CLI，reasoning effort high）、Qwen3-8B（4-bit MLX，贪心）、gpt-oss-20b、qwen3.6-35b-a3b（思考关掉，LM Studio，温度 0）。gemma-4-12b-qat 没过 12/12 准入，0/12 精确，解码 20.7，答案以泄漏的推理通道文本开头；论文不据此谈 gemma 的修复能力。每个任务每个臂 8 个格子：补丁或全文、diff 开或关、片段顺序正或反。测试划分每个臂 456 次尝试（52 × 8）。

3开源权重上也降

模型修复另计一列：每个臂 456 次尝试，簇均值的每次尝试错误放行率。T 臂和 E 臂的可见输入同时进修复提示和门；门失败时 gated 分支再给一次 pass/FAIL 反馈、不给期望值的修订。表 3 / 表 4 的错放是修订之后的数。原文没有把「门挡住」和「模型看见边沿输入后改写」拆开。作者边沿输入在三个开源权重家族上都降了这一列，正确完成没有掉。预注册的跨家族复制标准要求至少三个家族、且每个确认性家族的 H1 都通过；阈值按五个家族定，gemma 没过准入后用四个，论文单列这条偏差。按四个家族计，标准达到了。

4盲写、自测、硬干扰是辅线

盲写最多三条输入，任务均值放到 0.070；去掉 3 条等于隐藏输入的，是 0.090。第一阶段假拒绝没升，仍是 0.010。这条曲线预注册时不是假设，修任何代码之前就算过，而且只有一个写器，论文写成描述性。预注册的带守卫门只留写器标成「旧输出仍约束」的输入，放到 0.157，超过 0.10 的天花板，M4a 未通过。写器把 176 条里 35 条标成非约束，这些里偏多的是能让未修过程可见失败的：G3 下 42/52，W3 下 50/52。

自测每个家族都降了错放次数：22→9、98→80、71→47、49→30，各 456 次。没有一条 Holm 校正后显著。最小的严格 Holm p 是 gpt-oss-20b 的 0.132。自测复制标准未达到。Qwen3-8B 只在 30/73 个任务上写出至少一条有效自测；GPT-5.6-luna 是 71/73。

第二阶段菜单扩到 1491 个片段、1986 个过程。典型输入 FA 0.278，边沿 0.045，盲写 k=3 为 0.053。盲写这一档假拒绝从 0.014 升到 0.043。LM3 没按「菜单变大、典型门更松」的方向走：簇均值 0.406 到 0.271，多数新加的错误片段在典型输入上已经可见失败。论文写：门放行多少错程序，取决于菜单怎么建。0.410 和 0.278 只挂各自的菜单，不是门的属性。

第三阶段加了 233 个硬干扰片段：在典型输入上，新运行时的输出等于旧程序在旧运行时的输出。2310 个过程。典型输入放行 0.337，硬错误程序上是 0.990，按构造如此。边沿输入整体 FA 0.058，硬错误程序上仍是 0.168。盲写 GPT-5.6-luna 整体 0.058，硬错误 0.153，假拒绝从 0.010 升到 0.042。两个本地写器没过预注册：qwen3.6 整体 0.094，假拒绝从 0.010 升到 0.083，升幅超过容许的 0.05；Qwen3-8B 写器 0.182。

这些是同一篇文章里的其他结果。标题只挂第一阶段完整空间上 0.410 对 0.065。

5你的发布门

读完要核对的是发布位。Agent 改完依赖、升完运行时，你用来放行的那组测试，是不是只用了仓库里现成的典型样例。这篇里，405 片段菜单上，全断言门在典型输入上放行 0.410 的隐藏错误程序；同一组断言加上一条按发布说明写的边沿输入，份额是 0.065。两组测试用同一组断言，输入不同。模型修复那一列里，边沿输入同时进了提示，门失败还有一次修订，原文没拆开。

论文讨论给的廉价步骤：隔离模型按发布说明写几条边沿输入；在旧运行时上算出期望输出；用这些输入挡修复。预注册通过的写器只有 GPT-5.6-luna；两个本地写器没过。第一阶段盲写假拒绝没升；大菜单从 0.014 到 0.043，硬菜单从 0.010 到 0.042。不要让写器自己决定哪些旧输出还约束——预注册守卫正好丢掉了能揭变化的输入。自测多一次调用，Holm 之后站不住。弱修复器从强写器获益更多：事后 21 个任务矩阵上，GPT-5.6-luna 写器对各家族最好或并列最好；同模型格子均值 0.161，跨模型 0.187。这是事后、一个提示、四个家族，论文写成待预注册的假设。

下面是我的推断，原文没测编码仓库的 CI。如果你的发布门是「绿测就合」，而绿测的输入来自旧版本的 happy path，升 CPython / Node / SQLite 这类会改返回值、不改报错的变更，错修可以无错通过。10-25 那篇查的是规格没写的名字挡住单元测试；这篇查的是测试已经绿了、隐藏契约仍判错。两缝相邻，分母不同。

6这篇没测到的

修复是在文档化片段里选，没有跑自由书写再执行的那一臂。该臂只批准在严格沙箱里跑，研究机权限建不出 runner，没有换主机，论文不把效应外推到自由书写修复。25 个任务选项仍少于 15。硬干扰仍由作者用文档化算子生成。作者边沿输入和隐藏输入都从同一份发布说明写；威胁表仍写 hidden inputs are still author-written。73 个任务是 55 个旧任务整份导入加 18 个新的；测试划分 52 个受影响任务里，15 个簇是新的，主对比 0.410 对 0.065 与前序研究（55 任务上 0.377 对 0.065）大部分重叠。边沿列的 52/52 可见失败是质检规则强制的。

契约没有人类签字。两次盲 GPT-5.6-luna 审计，条目一致率 0.91（κ = 0.73），73 个任务里 34 个至少有一条双否。去掉有争议的文件保留检查 p0，以及再去掉旧值相等 d0，测试任务的穷尽隐藏判决改动 0 条。R2 类标签异议还开着：两个 Node.js 任务引用的是弃用史，不是删除本身。预声明的强证据标准没达到：M4a 未通过，AI 标出的任务超过 10%。

写器、审计器和一个修复器都是 GPT-5.6-luna。只有这个前沿写器过了预注册，两个本地写器没过。没有 Web API，没有更多运行时谱系。Python 和 Node 发布说明是公开的；SQLite 3.54.0 在 2026-10-09 发布，论文写成晚于模型可能的训练截止。无文档探针里，luna 在 37/45 个 CPython 任务上仍给出隐藏正确的第一步修复；原文写 The probe therefore bounds what release notes add to repair，不拿来解释门。

工件不公开托管，向作者索取。隐藏契约是评测钥匙。商业模型回复的再分发条款未清。
