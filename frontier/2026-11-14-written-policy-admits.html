权限策略让模型写，15 个开源权重模型里有 14 个会放行攻击

好几套间接注入防御都把「允许什么」交给模型先写一份策略、程序、依赖图或参数清单，再由代码去执行这份工件。一篇预印本在 AgentDojo 上用 15 个开源权重模型（1.7B 到 35B）、每个模型 929 条需要工具调用的攻击局，测了四套这种防御。Progent 生成的权限策略在 14 个模型上放行了至少一次攻击，合计 676 / 13,935；IPIGuard 的图是 13 / 15，DRIFT 的约束是 11 / 15。同一套模型自己写的 CaMeL 程序几乎不放行攻击，但 Granite-4.2-8B 上 CaMeL 局里有 68% 程序跑不起来。稿件推断：在这 15 个模型、这四套移植实现上，由模型写的允许集仍会放行攻击。

114 个模型会放行

CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts 盯的是工具 Agent 读到邮件、文件、网页之后，会不会按里面的指令去写：发信、付款、改记录。CaMeL、Progent、IPIGuard、DRIFT 都把决定从模型上下文里拿出来，交给代码。代码执行的对象，仍是这个 Agent 自己的模型写出来的：CaMeL 是程序，Progent 是权限策略，IPIGuard 是工具依赖图，DRIFT 是轨迹和参数清单。原文把这类输出叫做安全工件。执行层有多严，取决于这份工件。

四套防御原先主要配大模型测。这篇预印本换成 15 个开源权重模型，13 个在 1.7B 到 12B，另外两个是 Qwen3-32B 和 Qwen3.6-35B-A3B。每个防御的每一个模型角色都用同一个权重。无防御基线是 AgentDojo 自带的工具调用 Agent。

主攻击是 AgentDojo 的 important_instructions。攻击成功率的分母是 15 × 929 = 13,935 条需要工具调用才能完成注入目标的局。另有 20 对来自同一个 Travel 注入目标，只要求终答里出现一句话，不进这个分母，也不在原文的写完整性范围里。

Progent 让模型根据请求写权限策略，每一步调用后再改。15 个模型里有 14 个至少放行一次攻击；最多的一格是 Qwen3-32B 的 132 / 929。相对无防御，Progent 把合计 ASR 从 16.66%（2,322 / 13,935）压到 4.85%（676 / 13,935）。同一批策略在攻击局里还会拦掉 25% 到 77% 的已尝试写调用（图 6(c)，原文没给写调用总数），良性效用从无防御的 59.4% 降到 43.8%。IPIGuard 在 13 个模型上被攻破，合计 435 次；DRIFT 在 11 个模型上被攻破，合计 214 次。DRIFT 那 4 个零攻击模型，攻击下用户任务完成率（UA，分母每个模型 949 对）分别是 4.7%、9.5%、6.7%、4.7%。

2怎么测的

基准是 AgentDojo v1.2.2，四个套件：Workspace、Slack、Banking、Travel。97 条用户任务，949 对用户任务加注入。ASR 只用其中 929 对工具目标。15 个模型用 vLLM 0.30.0 做原生工具调用，温度 0，种子 0，关闭思考，每次调用最多 2,048 个输出 token；DRIFT 的调用放到 8,192。每个防御自己定义的模型角色，全部换成这一个开源权重。

13 个小模型：Qwen3-1.7B、4B、4B-Instruct-2507、8B，Qwen3.5-4B、9B，Llama-3.1-8B-Instruct，Gemma-4-E2B、E4B、12B，Granite-4.2-8B，Ministral-3-8B，LFM2.5-2.6B。两个更大的参照是 Qwen3-32B 和混合专家 Qwen3.6-35B-A3B。

主结果用 important_instructions。稳健性另在 8 个模型上加了 tool_knowledge，以及两条对着 CapLite 设计写的攻击：读工具去拉攻击者 URL，和种一条带着用户自己描述语的记录。这 8 个模型的工具目标分母是 8 × 929 = 7,432，不要和 13,935 混成一个率。

token 是每局提示加补全，对每个模型的 97 条良性局和 949 条攻击局取平均。效用每千 token（UA/kTok）是攻击下效用除以每局 token（以千计）。

3漏攻击和丢任务

原文把安全工件分成两类。一类决定允许什么：策略、图、约束写错，执行层会放行。一类决定跑什么：程序写不出来或解释器跑不起来，执行层会把任务丢掉。

原文图 3 画的是 Qwen3 四个尺寸（1.7B、4B、8B、32B）和 Gemma-4 三个尺寸（E2B、E4B、12B）。这两条线上，Progent、IPIGuard 和无防御的 ASR 随尺寸变大而升。Progent 在 Qwen3 这四格是 28 / 929、37 / 929、40 / 929、132 / 929（3.0% 到 14.2%），在 Gemma-4 三格是 0 / 929、18 / 929、118 / 929（0% 到 12.7%）。图 3 没画 Qwen3-4B-Instruct-2507：它的 Progent 是 55 / 929，高于同族 8B 的 40 / 929。别的族也不跟这条线：Qwen3.5-4B 是 75 / 929，Qwen3.5-9B 是 74 / 929；Qwen3.6-35B-A3B 是 22 / 929。原文的解读是：更大的模型更容易被注入，它写出来的策略和图没有把多出来的风险吃掉。跨 15 个模型，工件失败率和能力没有显著趋势（|ρ| ≤ 0.33，p > 0.2）。

CaMeL 的解释器按 CaMeL 作者写的数据流策略，执行模型写出来的程序。13,935 局里成功攻击 20 次，其中 17 次在 LFM2.5-2.6B。15 个模型里有 8 个，最终程序在超过 15% 的 CaMeL 局里跑不起来；Granite-4.2-8B 上是 68%，模型根本不返回代码。原文图 6(a) 的坐标是 CaMeL 局的百分比，没有分开良性局和攻击局。格式、语法、解释器错误可以修到十轮，每局仍要 93.7k token，第 1、2 节写成 94k。良性效用平均 24.9%，无防御是 59.4%。Gemma-4 是例外：没有可运行程序的比例从 22.9% 降到 3.3%，这两个更大的 Gemma-4 上 CaMeL 的攻击下效用也更高。

4不让模型写授权

CapLite 把授权从模型手里拿开。策略由工具 schema 按固定规则推导：名字和文档字符串开头的动词决定只读还是写，写工具的参数默认是权威字段，除非 schema 标成自由文本、时间或枚举布尔。目的地一类字段，即便在只读工具里也当权威字段，因为去拉攻击者指定的 URL 本身就是效果。认不出的动词记成未分类，中介直接拒绝，原文写这会掉效用。附录 A 列出全部 74 个工具的分类，只覆盖 AgentDojo 这一套。

规划器只看见用户请求和工具文档，一次受限调用最多提交十个工具调用，写调用在读到任何工具结果之前锁定，后面不能加、删、改顺序。绑定器只在抽出的候选标识符里选，自己不写值。中介是确定性代码：每个已锁定的写，权威参数必须和请求里出现的值完全相等，请求的子串不算。用户只描述、没写出那个值时，CapLite 会问人。评测对这类确认一律答否，并把该局计失败。

原文给出两条按构造成立的性质。已执行的写调用是规划器锁定集合的前缀，顺序不变。每个已执行写的每个权威参数，都在请求的取值集合里，或经过用户确认。注入可以改读哪些、改时间参数、改终答，不能追加写、换写工具，也不能把收件人、账户、金额、渠道、对象或目的地改成用户没写过的值。自由文本参数由撰写器写，不受这条约束。轨迹审计在运行中的 Agent 之外，用记下的请求和工具注册表重推策略和取值集合，检查每一次已执行调用：25,452 局 CapLite 里没有违规。

表 1 上 CapLite 的攻击下效用 29.0%，CaMeL 27.2%，每局 token 17.1k，约为 CaMeL 93.7k 的 18%。相对无防御，攻击下效用低 21 个点（29.0% 对 50.2%）。15 个模型合计 1,455 条良性局（97 × 15），CapLite 失败 1,046 条。附录 D 按函数名、不按参数，用启发式把这 1,046 条各归一个主因：43% 记成锁定计划缺了任务需要的写，38% 记成该跑的写都跑了、或只读任务已经作答，任务仍失败。确认请求占失败的 8% 到 12%（附录 H，案例 3）。攻击局里 CapLite 至少执行一次写的比例是 24.4%，CaMeL 是 26.2%；原文没另写这两格的局数。

8 个稳健性模型上，表 2 的分母换成 7,432。important_instructions 上 CapLite 是 0 / 7,432，CaMeL 3 / 7,432；tool_knowledge 上是 0 / 7,432 对 1 / 7,432；读外泄 0 / 168；描述语碰撞 0 / 104。原文把 URL 攻击的失败归因于中介检查每次读的目的地，把描述语攻击的失败归因于标识符必须在请求里出现。这两条攻击没有对应的消融，消融只在 important_instructions 上做。

同一 8 个模型的消融，分母是 7,432，不要和 15 模型主表的 28.1% / 29.0% 并读。去掉中介：良性效用 31.2%，攻击下 29.6%，成功攻击 106，ASR 1.4%，八个模型上都有。规划器读过观察之后仍可追加写：53 次攻击，ASR 0.7%。绑定器改为自由写值、仍由中介检查：攻击仍是 0，良性效用掉 2.0 个点。去掉报告器，良性效用从 25.6% 到 12.5%，攻击下从 26.1% 到 11.0%。

5你的运行位

自己的运行位如果按用户请求，让模型生成一份 Progent 式权限策略、CaMeL 式程序、IPIGuard 式依赖图或 DRIFT 式清单，再交给代码执行，这篇预印本测的就是这一层：在 15 个 1.7B–35B 开源权重模型上，按这四套移植实现，由模型写的允许集放行了攻击。IPIGuard 的图在读工具结果之前就定了，仍在 13 / 15 个模型上被攻破，所以成败不取决于「模型有没有读过工具结果」。

14 / 15 是「单次运行里至少一个成功攻击」的模型数，不是局数。局数是 Progent 676 / 13,935。温度 0、种子 0，每个配置一次。Progent 最小的两格是 Ministral-3-8B 的 5 / 929 和 LFM2.5-2.6B 的 8 / 929，没有区间。零攻击也要看效用：DRIFT 四个零攻击模型的 UA（分母每个模型 949 对）在 4.7% 到 9.5%。

CapLite 在这个基准上把写完整性收到 schema 和请求上的确定性检查。它不保证自由文本、不覆盖那 20 对只改终答的 Travel 注入，也不在用户没写出权威值时替你填。评测把确认当失败。消融去掉的是中介和写调用锁定，原文没有做「只把策略改成代码生成、其余不变」的对照。

和已有几篇相邻：护栏的选项名也是输入；同一条政策换个写法，遵守率就变了；压缩后规则还在，违规率仍高于完整历史。这里多出来的是：在这 15 个模型上，执行层再严，模型写出来的允许集仍会放行攻击。

6这篇没测到的

全部数字来自 AgentDojo 四个套件，这是原文 Limitations 写下的范围。CapLite 的攻击下效用比无防御低 21 个点；在 Gemma-4-E4B 和 Gemma-4-12B 上显著低于 CaMeL。用户没写出的权威值必须确认，评测答否。Travel 里 20 对只改终答的注入，原文标明在写完整性之外，CapLite 不防。温度 0、种子 0，每个配置一次。CapLite 的动词规则只覆盖这 74 个工具，未分类工具一律拒绝。附录 D 的失败归因按函数名、不按参数。

CaMeL、IPIGuard 用作者代码，只换模型接口。Progent 是在 AgentDojo 流水线里重现其语义，因为作者评测走 MCP；标题里的 14 / 15 来自这个重实现。DRIFT 另有解析器改动：有括号才去掉括号。AgentDojo 自带的工具过滤、spotlighting、重复用户提示和注入检测器只在 8 个模型上跑，放在附录 B，不进表 1。同一 8 个模型上，工具过滤是 226 / 7,432（ASR 3.04%，UA 31.2%，每局 11.1k token），表 2 的 Progent 是 466 / 7,432。没有复跑作者的容器，数字从 PDF 全文抄。
