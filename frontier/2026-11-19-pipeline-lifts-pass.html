需求流水线之后，held-out 过测从 21.9% 到 33.3%

一篇预印本固定基座模型，只改编码 Agent 的 harness。流水线是：模拟用户多轮提 issue，Triage / Architect / PM / Developers 写可复用改动，合入看 LLM 角色对模拟会话证据写下的需求是否过审。基准分留到进化之后评。原文没有「同一条流水线只换合入门槛」的对照。Harbor-index 38 道留出题、执行模型 GLM-5.3-Flash、评测带交互、三次运行平均：起始 Base Harness 的 pass@1 是 21.9%（±1.5），这条流水线产物 AHE-Beta 是 33.3%（±6.1）；执行 token 从每题 2.40M 到 1.42M，少 40.8%。同一套对照里，Claude Code 2.1.119 是 27.2%（±1.5），已发布的 AHE 是 23.7%，Meta-Harness 是 21.1%。

1过测 21.9% 到 33.3%，流水线一起换的

预印本 Agentic Harness Engineering Beta: Requirement-Centered Evolution of Agent Harnesses 固定基座模型，只改外围的提示、工具和中间件。作者把这套外围叫 harness。进化从一份 Base Harness 出发，最多 32 个种子、六轮；每一轮先让用户模拟器干活、提 issue，再由一组角色改仓库。方法写法是：PR 要过 admission 和 review，正文写合入步骤不查基准分。这是整条流水线的说明，不是「只换合入门槛」的对照。附录 E.1 写，这些机制是工程解释，没有把单项效应分开。

标题里的两个率来自主对比：38 道 Harbor-index 留出题，评测协议带交互，执行模型 GLM-5.3-Flash，三次运行的平均。pass@1 是每题一次尝试、事后审计过的通过比例。Base Harness 21.9%（±1.5），AHE-Beta 33.3%（±6.1）。token 是每题平均执行 token，单位百万，不含用户模拟：2.40 对 1.42。用户评分是模拟器在 1–4 分上的均值：2.59 对 3.04。人的 A/B 用 1–7 分，分母和刻度都不同，下一节分开写。

AHE-Beta 这个名字指 N=32 那条主配置。N=8、N=16 是另开的进化，种子更少。已发布的 AHE 是另一份冻住的 harness，表里过测也是 23.7%，和 N=8 关掉交互那条碰巧同数，不是同一件东西。

2三步：issue、改 harness、角色过审后合

一轮里，用户模拟器只看见面向用户的回复和进度，看不见 harness 源码。人设库有 50 张卡，七个维度包括验收门槛、自主程度、会不会核结果。进化时每个种子配一张人设；评测时换成一张固定的评测人设。模拟器先用自己的话写下下一步打算，再从菜单里选动作，并记下打算和菜单对不上的地方。会话中途可以提 issue，结束打用户分。

Triage 一次看一条 issue，连同该会话的交互记录和当时的 harness 提交。它丢掉「这是这道题的事、不是 harness 的事」、站不住、或当前 harness 已经满足的条目，把剩下的改写成不带项目名、任务号和具体答案的需求。Architect 把同根因的需求合成一条机制级需求，至少引用两条。PM 每轮最多写三份产品需求，走会话评分和摘要，不经过 Architect。Developers 按共享接口排序，先写 RFC，再开 PR。

合入：PR 要过 admission 和 review。「已核需求」是 GLM-5.3 的 Triage、Architect、PM 对模拟会话证据的核对；证据来自 GLM-5.3-Flash 用户模拟器，进化会话里没跑过任务验证器。代码审查按 RFC 的验收条件做，图 1 写 Review and merge by the Developers，写代码和过审是同一类角色。原文未描述人工环节；没有写外部真值核验。附录从表 11 的冻结 Gitea 记录抄：N=32 的第 1 到 5 轮（第 6 轮只跑会话）共 131 条 issue，Triage 拒 36 条，写出 115 条需求，合成 22 条，另有 14 份 PRD，合进仓库 71 个 RFC。第 5 轮还有 4 条 issue 仍开放。正文写，没有一步去查基准分。

执行模型和用户模拟器都是 GLM-5.3-Flash。Triage、Architect、PM 是 GLM-5.3。Developers 跑 Claude Code CLI，经 Anthropic 兼容接口调 GLM-5.3。进化各配置各跑一轮。评测主对比三次，其余配置一次。

338 道留出题上的主对比

38 道题按域：Coding 14、Optimization 12、Analysis 7、Tool Use 5。附录 C 列出题名。正文写，进化用过的任务实例不在这 38 道里。Claude Code 用官方 npm 的 2.1.119，同一执行模型 GLM-5.3-Flash，经 Anthropic 兼容接口跑原生 CLI。Meta-Harness 钉在上游 57fefdb，是为 Terminal-Bench 2.0 发布的 harness，适配到 Harbor 0.24，保留默认 temperature 0.7。AHE 钉在 182ea06，运行时 NexAU 28511d9。这三份都是别人发布的冻住产物，不能当成「分数门槛」的对照。Meta-Harness 原文写是为 Terminal-Bench 2.0 发布的；进化用了什么模型和预算，原文没写，上一句不据此推断。主协议是带交互的评测：模拟器在每条完整回复之后再说话，直到自己结束或任务时限到。

按任务计，分母 38 道：AHE-Beta 的 pass@1 高于 Base 的有 12 道，低于的有 3 道，其余 23 道不变；用户评分更高的有 16 道，更低的 0 道，其余 22 道不变。按域，Tool Use 从 0.0% 到 26.7%（5 道），Optimization 从 19.4% 到 38.9%（12 道）。Coding 从 38.1% 到 40.5%，Analysis 从 9.5% 到 14.3%。用户评分上，Meta-Harness 1.69、AHE 2.53、Claude Code 2.46，都低于 Base 的 2.59；AHE-Beta 3.04。留出观测只在第 1、3、6 轮：pass@1 从 21.9% 走到 33.3%，用户评分从 2.59 走到 3.04。

4评测关交互，单次不低于另外两套

进化侧：N=8 的八个种子里六个带交互，held-out 过测 28.9%（11/38）、token 1.71M。同一套种子全部关掉交互（模拟器只看最终回复和只读工作区补丁再打分、提 issue）是 23.7%（9/38）、3.15M。差 2 道题，各跑一次。原文写开交互的 N=8 比关交互少 45.7% token，分母是 3.15M，（3.15−1.71）/3.15。关交互那条相对 1.71M 多 84.2%，两个百分比分母不同。评测侧这几行都带交互。表 2 是进化阶段开或关交互，不是合入门槛的消融。正文把差额写成：中途纠正和会话里才冒出来的需求，终局审查看不到。

评测侧再关交互：任务文本只发一次，没有模拟用户跟进，也就没有用户评分。表 3 这三行是单次运行，没有 Base，也没有 AHE。AHE-Beta 过测 26.3%（10/38）、token 1.55M；Claude Code 23.7%（9/38）、3.24M；Meta-Harness 13.2%、2.53M。差 2.6 个点是一道题。主对比里 AHE-Beta 带交互三次运行的标准差是 ±6.1。正文写优势不来自评测时用户帮忙；这一句限定在这三套、单次、差一道题。

过测和用户看见的东西对不齐。原文写 137 次过测会话里 34 次没有完整回复，用户评分落到下限 1：核验器读最终工作区，模拟器只看见 harness 报出来的内容。原文没写这 137 次由哪些 harness、哪几次运行构成，是跨配置合计，不是 AHE-Beta 主配置的率。其中 6 次来自 AHE-Beta（N=16），所以那条配置过测高于 Base，用户评分仍低于 Base。

附录 E.2：两边都解出的题上，token 相对 Base 仍少 53.6%，相对 Meta-Harness 少 37.4%，相对 Claude Code 少 41.6%，相对 AHE 少 29.7%。去掉贡献最大的 Doom 任务之后，相对 Base 仍少 30.6%。外部基线记录到的 token 大约 98% 是输入。

5换模型不重进化；人评是另一套

Flash 上进化出来的 harness 原样接到 GLM-5.3 和 DeepSeek-V4.1-Flash（2026-10-17 版），不再进化。附录 E 写主对比三次，其余配置一次；表 4 里只有 GLM-5.3-Flash 一行是三次平均，这两行是单次。pass@1：GLM-5.3 从 23.7%（9/38）到 39.5%（15/38），差 15.8 个百分点、6 道题；DeepSeek-V4.1-Flash 从 36.8%（14/38）到 42.1%（16/38），差 5.3、2 道题。用户评分：1.70 到 3.03（37 道有评分的配对），3.33 到 3.39（36 道）。token：GLM-5.3 从 1.91M 到 1.99M，这一格 AHE-Beta 并不更省；DeepSeek 从 3.80M 到 2.81M。pass@1 和 token 用满 38 道。

盲测 A/B 不是跨模型那两行。人评的是 GLM-5.3-Flash 上的 Base 对 AHE-Beta，默认推理设置，输出上限 65,536；主评测协议是 maximum reasoning effort。六项编码任务自选，两侧标成 A/B，A 在 48 对有效里有 24 对是 Base。每侧预算 30 分钟，T2 60 分钟，可延长。交了 50 对，去掉 2 对（一侧没收到用户消息；平局和文字理由打架）。48 对来自 25 个匿名标签。完成情况是自评，没有独立代码审查。有效对里 AHE-Beta 31、Base 7、平 9、两边都不要 1。Overall 均值（五个维度再平均）Base 5.39、AHE-Beta 6.01，刻度 1–7。过程可理解性 4.13 对 5.33。有用性和控制各缺 1 个评分。六对里 Base 一侧读到了上游补丁或等价修复，AHE-Beta 一侧审计确认没有；这六对里仍有五对选 AHE-Beta。去掉这六对：42 对有效里 26 对 6，另有 9 平、1 都不要。自评完成：AHE-Beta 41 侧，Base 34 侧。

6你的运行位

读完要看的是：自己改 harness、用 Agent 改 Agent 外围时，拿在手上的是一份 Base，还是跑过用户模拟加角色团队的产物。这篇在 38 道 Harbor-index 留出题上，过测从 21.9% ±1.5 到 33.3% ±6.1，token 从 2.40M 到 1.42M。同一执行模型上，这份产物点估计 33.3%，Claude Code 2.1.119 是 27.2% ±1.5；差 6.1 个点，跟 AHE-Beta 自己三次运行的标准差一样大。合入门槛没有独立消融。

稿件推断，不是原文部署实验：如果编辑起点把「这道 SWE 过了」写成合进默认脚手架的理由，而用户侧还在中途改口、要看见进度、要结果送到面前，这篇测到的是核验器和模拟器看不同一面。N=16 过测可以高于 Base，用户评分仍低于 Base，原文点名其中 6 次过测会话没有完整回复。137/34 是跨配置合计，原文没写分母构成，不拿来当 AHE-Beta 主配置的率。原文没测你仓库里的真实用户，人的 A/B 是六项自选编码任务、48 对有效、完成情况自评。

和已有几篇相邻：固定模型换脚手架，Qwen 正确率差 11.5 个点 讲的是同一模型换五套现成脚手架；可核指令 86% 以上全跟或从不 讲的是仓库指令落没落到提交上；条件写法相对规定和解释跟得少 讲的是同一条政策换句式。后几篇数字以各篇原文为准，本轮没有重开。这里多出来的是：跑过用户模拟加角色团队的 harness，在这 38 道留出题上过测从 21.9% 走到 33.3%。

7这篇没测到的

进化最多 32 个场景、六轮、一种模拟器模型、选定的人设，外加一场人的 A/B。局限节写，更宽的场景、更多模拟器模型和人设组合、继续迭代，对 harness 质量和算力的影响还没在更大尺度上评。主对比三次，进化本身各配置一轮。AHE-Beta 的 pass@1 标准差 ±6.1，宽于 Base 的 ±1.5。稿件推断：执行模型和用户模拟器都是 GLM-5.3-Flash，2.59 到 3.04 的用户评分不是独立于进化环境的指标；原文局限节没声明这一点。

N=16 过测可以高于 Base，用户评分仍低于 Base，因为过测会话里有没把回复送到用户眼前的。附录 E.3 写，失败会从早期执行挪到更后面的正确性、性能、抽取和副作用约束：Xarray 测试从 18 里过 8 到过 16，还剩两个网格边界；Pandas merge 从编译失败走到算对，速度门槛没过。剩下的失败分两类。第一类需要 harness 还没采到的核验证据；第二类是 Agent 说对了要求，脚手架给不出那份能力。

人的 A/B 任务自选，对计数不均（T2 只有 2 对，T3 有 13 对）。T3 13 对里平局 6、都不要 1，AHE-Beta 5、Base 1。完成是自评。六个 Base 读到上游补丁的对，方向仍偏向 AHE-Beta，但样本量小。进化 token 附录写成 N=32 已记录分量合计 1.92B，98% 是输入，Developers 约占 68%；覆盖不完整，不能拿去给各变体做全成本排名。

跨模型那两行没有再进化，也没有和「在新模型上重跑进化」对照。Analysis 域 7 道，AHE-Beta 过测 14.3% ±0.0，Base 9.5% ±16.5，这一格不要读成稳。Tool Use 5 道，26.7% ±11.5。
