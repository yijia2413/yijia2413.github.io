gpt-oss-120b 全量 199 条 51.2%，约 29 条 55.4%

一篇预印本给编码 Agent 塞自己挖出来的指南。AppWorld 的 test_normal 168 道题上，TGC 是整题评测检查全过的比例。gpt-oss-120b 无记忆 39.9%；把自己挖的 199 条全塞进去 51.2%；检索加高支持核约 29 条，两次运行平均 55.4%（56.0 和 54.8）。约 7 道题是原文的话；4.2 个点是稿件用 55.4 减 51.2 算的。全量是单次，检索是两次平均；约 29 条是四档里在 test_normal 上最好的一档，没有留出集。同一套 ReAct 里，DeepSeek-V3.2 从 0 条 79.8% 走到全量 191 条 89.3%。作者写：该注入多少是模型的属性。每个模型自己挖课，原文没有把模型能力和课的质量分开测。评测默认单次；作者把大约 5 道题以内的差当噪声。

1gpt-oss 全量 199 条低于约 29 条

预印本 How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents 把一条记忆流水线接到 AppWorld 的参考 ReAct 代码 Agent 上。每一步一次模型调用，写出 Python，环境回输出。TGC 是任务级：168 道 test_normal 里，评测检查全过的比例。SGC 更严：一个场景里所有任务变体都过，才算这个场景过。课只从 train/dev 挖。dev 已经拿去挖课，没有留出集选配置，各配置直接在 test_normal 上比。

标题里两个率都是 gpt-oss-120b、同一套 ReAct 脚手架。无记忆 39.9%。全量注入自己挖的 199 条，51.2%。检索配置大约 29 条：高支持核始终在，再按源任务相似度补 top-k，两次运行 TGC 56.0 和 54.8，平均 55.4%；SGC 取第一次的 37.5%。每题 token：无记忆 110K，全量 166K，检索 116K。作者写，检索和基线 token 差不多（116K 对 110K），全量大约贵一半。

24 条的支持≥3 核是 53.6%，比全量 51.2% 高 4 道题。作者写全量不优于这个 24 条核；4 道题低于他们说的约 5 道题噪声线。表 2 的「事先钉死」规则是一律注入全量：gpt-oss 仍从 39.9% 到 51.2%，+11.3 个点。检索约 29 条是这四档里在 test 上最好的一次，不是留出集挑出来的。DeepSeek-V3.2 按同一条全量规则走到 89.3%，+9.5 个点。

2课从自己的轨迹挖

Agent 先在 train/dev 上跑，成功失败都留。每条轨迹让同一个模型写 1 到 3 条祈使句，下次该怎么做。成败标签来自评测器，不来自模型自评。DeepSeek-V3.2：147 条 train/dev 轨迹，290 条生课，失败 62、成功 228。近重复会占满检索槽，所以再合成指南。合成按源任务嵌入聚类，簇内才合并，且只在「照这条做等于照那条做」时合并。每条指南记下合并了几条课，叫支持数；输出支持数之和等于生课条数。模型漏掉的课原样留下。DeepSeek 合成 191 条，其中 144 条支持数为 1。

交付可以全量静态注入，也可以检索：支持≥3 的核始终带上，再按源任务相似度加 top-k，已经在核里或互相重复的丢掉。按支持数卡阈值发生在选取时，不从仓库删。挖课、合成、跑 Agent 用同一个模型，没有单独的教师模型，也没有人工标。流水线在开源库 altk-evolve 里，接到 IBM 的 CUGA 和 watsonx Orchestrate。方法本身作者不当成这篇的贡献；写的是跨 40% 到 92% 基线 TGC 的模型，部署时踩到的事。

AppWorld 模拟九个应用，457 个 API，大约一百个模拟人，750 道题。全文主表用 test_normal 168 道；test_challenge 417 道只在点名处出现。八个模型打了基线，六个带着记忆跑。DeepSeek 五种配置，gpt-oss 四种，GPT-5.5 / GLM-5 / Gemma-4-31B 各两种，Claude Opus 4.6 一种。

3DeepSeek 加到 191 条还在涨

DeepSeek-V3.2 的 TGC：0 条 79.8%，12 条 82.7%，19 条 83.9%，47 条 85.7%，全量 191 条 89.3%。相邻两档差两到四道题，作者写单独看落在噪声里；端点差 16 道题。SGC 从 64.3 到 80.4。难拆分（原文 hard split）TGC 60.4 → 72.9，SGC 41.7 → 58.3。GPT-5.5 基线已在 92.3%，全量 207 条到 95.2% / 89.3%；TGC 大约五道题，作者写在噪声地板上，SGC 增益更大。GLM-5 72 条全量仍是 87.5%，饱和。Gemma-4-31B 记忆跑在 164 道子集上，全量 87 条 64.6%，基线 63.4%；括号里写全部 168 道的基线是 62.5%。原文写 Gemma too weak to apply memory：整体几乎不动，过紧的核反而有害。它没有「全量对精选」对照，不能当 gpt-oss 那条曲线的第二个例子。

按难度拆同一批运行（表 1）。原文没给分档的题数或场景数。百分数能还原成整分数，是稿件反推：DeepSeek 中档 SGC 62.5 → 93.8 对得上 10/16 → 15/16，差 5 个场景；gpt-oss 难档 SGC 4.8 → 9.5 对得上 1/21 → 2/21。这些分档不作标题论据。gpt-oss 表 1 用的是两次检索里第一次（TGC 56.0）：易档 66.7 → 82.5，中档 35.4 → 56.2，难档 19.1 → 31.8。Opus 4.6 在 test_challenge 上难档 TGC 73.3 → 83.1。Opus 在 test_normal 上只跑了压缩的 12 条，94.6% / 94.6%，基线 90.5%，没有全量数字。

4压缩、ACE、CUGA 是辅线

DeepSeek 上，第一版合成提示要一份短清单，得到 12 条，+2.9 个 TGC 点；全量 191 条 +9.5，两档差 11 道题。作者认为差在 144 条支持数为 1 的指南；原文没有单独去掉这 144 条的实验。上线后无损合成变成默认。一条高支持分页指南假定页上限 20，API 默认页长 5，基线已过的题回退；人手改写后难档 TGC 66.7 → 73.0。原文这一段没再写模型名；表 1 里 DeepSeek 难档无记忆 TGC 也是 66.7。作者写支持数量的是独立推导次数，不是正确性。

噪声。gpt-oss 同一检索配置两次 56.0 和 54.8。DeepSeek 相同配置之间，168 道里大约 32 道对调输赢，合计几乎不动。改进的题和回退的题，检索余弦均值 0.463 和 0.468。作者此后把大约 5 道题以内的差当噪声。和 ACE 的对比因此改口：gpt-oss 上相对 ACE 的「+1.2 TGC」收成准确率打平。原文还写 token 大约七分之一（116K 对 777K）；ACE 跑在 ACE-ReAct 上，本文跑在参考 ReAct 上，gpt-oss 没有 ACE-ReAct 无记忆基线可扣，这个倍数含脚手架差。

DeepSeek 上 ACE-ReAct 无记忆 72.0% / 57.1%、221K；加 ACE 的 106 条 80.4% / 73.3%、634K。本文 ReAct 无记忆 79.8% / 64.3%、148K；全量 191 条 89.3% / 80.4%、263K。相对自身基线，ACE +8.4 / +16.2，本文 +9.5 / +16.1。同一模型无记忆 token 已经是 221K 对 148K。全量 191 条比本文无记忆多 78% token；支持≥2 的 47 条多 27% token，TGC +5.9。步数 18.4 → 19.3。gpt-oss 上 ACE 全本 54.8% / 35.7%、777K；本文全量 51.2% / 32.1%、166K；检索 55.4% / 37.5%、116K。

CUGA 和 watsonx 是另一套脚手架，不支撑标题。修过写路径之后，GPT-4.1 在 AppWorld 168 道、三次平均：无损合成 TGC 71.03% → 72.42%（119.3 道变 121.7 道），SGC 54.76% → 58.93%（表注平均 30.7 个场景变 33.0），作者写大约两道题、低于噪声地板。τ-bench 零售 40 道测试、12 条支持≥3：均准确率 51.7% → 55.8%。GLM-5.3-Flash 自己挖 280 条课、164 条指南，每臂两次：无记忆 TGC 87.8，29 条 88.4，164 条 93.2。watsonx 给了一条费用报销的定性转移（13 步 18.53 秒对 10 步 11.35 秒），作者写时延不是受控估计。

5你的运行位

读完要看的是：运行位、编辑起点、技能记录里，记忆是全量灌进上下文，还是按模型改剂量。这篇在 168 道 test_normal 上，gpt-oss-120b 全量 199 条 TGC 51.2%，大约 29 条 55.4%；DeepSeek-V3.2 全量 191 条从 79.8% 到 89.3%。事先钉死的全量规则让两个模型都不低于无记忆。gpt-oss 的最好一档是检索，全量低大约 7 道题；约 29 条是四档里在 test 上挑的，没有留出集。Gemma-4-31B 没有全量对精选对照，原文写它弱到用不上记忆，过紧的核反而有害。

稿件推断，不是原文部署实验：若默认是「课越多越好」，这篇在 gpt-oss-120b 上测到全量低于约 29 条。每个模型自己挖课，原文没有把「容量吃不下」和「课写得差」分开。压缩掉支持数为 1 的课，是作者对 DeepSeek 12 条对 191 条的解释，没有单独消融。支持数高的分页指南仍能把已经过的题打回去。产品化时出过两次错：整合按固定字段表重建元数据，丢掉支持数和生成方式标签；LLM 在一次合并里重复同一个下标，支持数被重复计数。后面的选取依赖这些字段还在。

和已有几篇相邻：给下一道未知任务的记忆，该留路径和检查命令 讲的是轨迹里哪一段该留下；Agent 记忆由哪些部分组成 讲 Anthropic 的记录、整理、取回分工；固定模型换脚手架 讲脚手架本身。后几篇数字以各篇原文为准，本轮没有重开。这里多出来的是：gpt-oss-120b 上，全量 199 条低于大约 29 条。

6这篇没测到的

主表默认单次运行。噪声节写 DeepSeek 相同配置之间大约 32 / 168 道对调，gpt-oss 两次差 1.2 个点。作者把大约 5 道题以内当噪声；DeepSeek 相邻剂量差两到四道题，单独一档不够立论，端点 16 道题才拿来写趋势。dev 用于挖课，配置是在 test_normal 上比出来的；表 2 因此并列「事先钉死的全量」和「test 上最好的一档」。gpt-oss 的 55.4% 是两次平均，51.2% 是单次，全量那一档没有重复运行。

六个带记忆的模型各自挖自己的课，不能把 DeepSeek 的 191 条接到 gpt-oss 上读。原文也没有交叉实验，所以「该注入多少是模型的属性」没有把能力和课的质量拆开。Opus 4.6 在 test_normal 上只跑了 12 条压缩集。Gemma 记忆跑在 164 道子集，没有全量对精选。ACE 对照在同一模型、同一拆分上重跑，但 DeepSeek 的无记忆基线差 7.8 个点，作者把头条分差收成脚手架。gpt-oss 的 ACE 行没有给出 ACE-ReAct 无记忆基线。难度分档的 SGC 原文没给场景数，稿件反推分母只有十几到二十个场景。

没有正确性或新近性信号，也没有自动降权。CUGA 的 GPT-4.1 数字低于噪声地板。GLM-5.3-Flash 的 164 条是第二条脚手架上的强模型曲线，29 条压缩集不涨。watsonx 那条是单次定性。失败会静默：温度 0 被 GPT-5 档接口拒绝、合成截断 JSON、写路径从未调用，日志仍像跑完。这些没有单独的对照实验。
