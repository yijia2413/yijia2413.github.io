FRONTIER · 2026-11-24 · Agent Tools

兼容更新加了坐标，行为能确定的六家都不重批

一篇 ICAART 2027 录用稿、arXiv 预印本看 MCP 工具的输入 schema。旧调用仍合法，新参数已经进来。Desktop Commander 0.1.34 的 execute_command 只要 command 和 timeout_ms，关着别的字段；0.1.35 加上任意字符串 shell。作者抽了 39 个公开 MCP 服务器、604 个发行版。1,197 条工具 schema 变化里，580 条兼容；412 / 580 条加宽了某个坐标（无标签口径）。作者双人标注至少 76 条加了或加宽了带权限的参数。调查 8 家客户端和扫描器：4 家跑过，VS Code 只读源码，Claude Code 只读文档；这 6 家行为能确定的都不对加宽重批。Claude Desktop 和 Cursor 只看文档，标成无法判定。

1兼容还能加 shell

预印本 SchemaCaps: When a Compatible Tool Update Silently Widens an AI Agent’s Authority 看的是已经批过的工具，发行版换了输入 schema 之后，委托还在不在原来那条边界上。MCP 把工具写成名字、描述、参数 JSON Schema。用户批一次，Agent 按这个 schema 调。服务器是普通包，几天一个发行版，会话中途也能改工具列表。

兼容的定义：旧调用在新 schema 里仍合法，写作 [[S]] ⊆ [[S′]]。权限坐标是参数路径，再加上每个对象上「未声明字段」那一格。加宽指这些坐标上的有效值集合变大：新字段、枚举变宽、对象打开、新允许 null、默认值改掉。作者把 shell、webhookUrl、目标项目当成带权限的参数，因为取值决定在哪跑、数据去哪、对谁动手；limit、分页游标不算。没有名单时，每条未标路径都当带权限，这是无标签默认。

Desktop Commander 0.1.34 → 0.1.35：execute_command 在关着的对象上加上 shell，任意字符串。旧的 command 调用仍过。写给某一个解释器的策略，解释器改由 Agent 选之后就管不住。同一套回放里还有 Firecrawl 的 webhookUrl、GitLab 的 target_project_id、Sentry 的 regionUrl、Notion 打开的 parent。代理在抽出的工具列表上跑决策，没有起真实服务器：兼容规则 6/6 条静默重绑；原文写 pinning 和 SchemaCaps 6/6 条挂起，没有写 pinning 是钉整份定义还是只钉输入 schema，也没有写 SchemaCaps 用哪一档。

精确对照基准有 600 条合成变化，其中 330 条加宽。送审版规则对这 330 条里的 27 条静默重绑（关掉两处新检查来模拟），后来补了两处：关掉的对象上删掉必填或带默认的字段，以及在已有类型化 additionalProperties 之外再声明字段。修过之后，无标签模式在这份基准上 0 条加宽被静默重绑。第二个种子 333 条加宽里，修前 33 条、修后 0 条。这是作者自己的 15 个变异算子、有限关键字集合；第二个种子复用同一生成器。135 条旧 schema 把兄弟字段绑在一起的变化直接当未知去问，没有做包含检查。修过之后，试点的无标签计数不变，名字规则只多 1 次重批。这是合成基准，不是试点语料。

2580 条里 412 条加宽

试点用来证明兼容加宽在公开服务器上存在，并量几种规则各问几次。作者写明这不是生态发生率。协议 2026-09-29 15:25 UTC 哈希，语料抽出之前；没有交给第三方托管，顺序是作者自证。窗口是 2025 年 1 月到 2026 年 9 月的稳定发行版。层 A 官方参考服务器，层 B 下载量最高、能用空凭证答 tools/list 的 15 个第三方 npm stdio 服务器。每个包最多 20 个发行版。抽样 657 个发行版里 604 个答上（91.9%），39 个包，565 对相邻发行版。HTTP、只认证可答、PyPI 第三方服务器不在池里。

单位：发行版是一个包的一个公开版本；一对是同一包相邻两个发行版；一条变化是两版都有的同一工具、输入 schema 不同；兼容指旧调用仍合法。

表 4 另给严格口径：用名字角色套定义 1，兼容且加宽 274 条。核心 84 条全在层 B，落在 6 个服务器、228 对里的 20 对。两个包占 62 条：一个移动自动化服务器给 37 个工具加了两条本地路径，一个错误跟踪服务器给 15 个工具加了区域端点。拿掉第一个剩 42，拿掉第二个剩 64，两个都拿掉剩 22。核心占 580 条兼容变化的 14.5%。按包有放回重抽 10,000 次，固定种子，区间 [3.5, 25.2]%；无标签加宽是 [56, 86]%。作者把它写成稳定性检查，不是总体估计。

带权限这一格靠人标。第一次按结构读权限，作废。按第 2 节标准，两名作者盲标 176 例参数：抽表时兼容变化里带询问理由的 44 个被标参数（最终分类器下是 50 个，另外 6 个没有核心理由），加上关着的祖先下新加、名字规则没标的 132 个，用来看漏标。第三人裁定 29 处分歧。原始一致率 84%（RESULTS.md 写 83.5%），分母 176 例，Cohen κ = 0.67。对照裁定标签，名字规则精确率 0.75、召回 0.60，单位是参数；召回是上限，漏标只在新加参数里抽。84、66、76 是变化条数。84 是名字规则的核心变化条数。裁定确认其中 66 条，另找出 10 条它漏的，合计至少 76。送审稿写成 73（66 + 7）。默认规则不用名字标签。

已有工具上各规则要重批几次：钉死整份定义 2,004 次，其中 807 次只改了描述或标题；只钉输入 schema 1,197 次；兼容规则 617 次；无标签 SchemaCaps 645 次，比兼容多 28 次（+4.5%）；名字规则 413 次，漏标另算。907 个新加工具每条规则都当新权限，加上去：钉死整份 2,911，兼容 1,524，无标签 1,552，名字规则 1,320。原文没给只钉输入 schema 加上新工具后的总数。20 次检查答未知。作者写，645 次询问里有多少会被委托人觉得多余，这篇没测。

行为能确定的 6 家都不对加宽后的工具重批。另外两家闭源，文档也没写这种检查，原文标 not determinable。只读文档的归类可能和实际行为不同，这一条也套在 Claude Code 上。Vercel 的漂移检测是可选、报任意变化。mcp-scan 钉的是描述。作者写：部署客户端，就他们能确定的范围，不问「权限坐标有没有变大」这件事。

4你的运行位

稿件推断，原文没测这些场景：工具批准如果绑在名字上，发行版加一个 shell 或 webhookUrl，旧批准还在。技能记录和编辑起点如果只存「这个工具已批」，对不上 schema 摘要。把输入 schema 的哈希写进批准记录，加宽就打断；代价接近钉输入 schema 的 1,197 次询问。只在兼容性上放行，会静默重绑试点里 412 / 580 条无标签加宽；其中人工确认带权限的至少 76 条，名字规则 84 条里有 62 条来自两个包，严格口径 274 条。无标签把未标路径都当权限，412 是上界，不是人工确认的权限提升比例。

无标签默认把未标路径当权限，询问次数靠近兼容规则（645 对 617），按构造拦住那 412 条。行为改了、schema 一字不差，原文表 3 该行所有规则（含 Accept-all）都 succeeds，共 6 列；原文写 defeats every rule。

11-17 那篇测的是两台 server 摊在一起、同名抄描述时模型绑到哪一家。这篇是已经批过的同一把工具，schema 自己长大。两条缝可以叠：先被同名工具骗走，再被正主的兼容更新加权限。09-26 的 RSI 谱系和 09-27 的增量分层不覆盖 schema 重绑。

5这篇没测到的

  • 试点不是随机样本，加宽集中在少数服务器，不外推 HTTP 服务器或其他仓库。
  • 标注人和裁定人都是作者，独立性不能外证。分类器有事后修正。
  • 检查器用 jsonsubschema，失败当未知；对布尔相对枚举曾给出假 yes，作者改写成显式枚举，并加 60 次、2 秒的反例搜索。检查器经过测试和守卫，没有形式化验证。
  • 演示规划器是脚本，服从注入、不跑 LLM。真实案例只在抽出的 schema 上重放，没有执行外部效果。
  • 8 家里 4 家跑过，1 家只读源码，3 家只读文档。Claude Desktop 和 Cursor 标无法判定。只读文档的归类可能和实际行为不同。
  • 同一 schema 背后的行为变化、配置出来的服务器默认值、输出 schema、描述注入，原文写在范围外。
  • Coq 证明的是定义 1、乘积条件和链上命题，共 117 行、无公理无 admit；逐步包含关系来自检查器。
