过期测试命令让 Sonnet 多调用约两次工具（探索性）

仓库里一条过期的测试命令，可能让 Agent 多做几次工具调用。在一项包含 22 个维护任务的预印本实验中，Sonnet 5.5 遇到过期测试命令时，每任务工具调用中位数的平均值为 7.8 次，修正同一行后为 5.8 次。这是探索性结果：按估计数量校正后，区间不再排除零；Haiku 5.5 和另外两个案例没有检测到调用差。

1过期命令增加的工具调用（探索性）

编码 Agent 每次开始会话时都会读取仓库根目录的 AGENTS.md / CLAUDE.md。测试目录搬过了，文件还写着旧命令。论文把这条过期指令叫文档债：本金是改一行，利息是一次碰上多付的工。论文写利息还要乘上任务走到这一行的频率；这篇只测了前一半。

依据论文摘要和表 II（HTML）。Claude Sonnet 5.5 在过期测试命令上，每任务中位数再平均 7.8 次工具调用，改对同一行是 5.8，大约多两次工具调用、多三分之一。论文写 95% 区间不含零；按估计条数校正之后，区间不再排除零。标成探索性。Haiku 5.5 和另外两个案例，工具调用差检测不到。任务通过率几乎不动。

论文 Fig. 1 里那条 4 次对 6 次工具调用是作者挑的中位示例，与主要比较的条件不同。7.8 对 5.8 来自表 II 的 Sonnet 测试命令列。732 次没人改指令文件是同一跑次里的旁证：提示只有 bug 报告，任务没要求维护文档。

2三条过期指令与 22 个维护任务

三条过期指令都来自还在更新的开源仓库，当时写对、代码搬过之后文件还留着旧路径，中间又改过文件也没删那一行：测试命令 2 次后续编辑，代码位置 13 次，加组件手续 4 次。论文用脚本从抽样仓库抽出曾经存在、现在没有的路径，再用 Claude 和 Codex 两轮复核这条是否仍写成现行指引。搜索只用来找案例，不报过期率。

  • 测试命令：pyflow 的 AGENTS.md 写 pytest tests/ifds。测试在 2026-07-14 搬到 tests/analysis/ifds。8 个缺陷；每个修复都要用这条命令点名的测试来核。
  • 代码位置：cog 的指令文件写预测器接口在 base_predictor.py，文件已搬走。6 个缺陷都在同一包里，没有任何任务需要那份旧文件。作者拿它当对照：Agent 就在旁边干活，会不会被拽走。
  • 加组件手续：aghub 的 CLAUDE.md 把新 agent 写进 crates/core/src/agents/，代码已搬到单独包。仓库里另一份指令文件已经写了新位置。8 个缺陷。

每个任务三种条件：过期原样；改成代码搬走后的路径；删掉这一行、文件其余不动。代码、缺陷、bug 报告钉死。Agent 是 Claude Code 2.1.316，medium effort，30 分钟上限，每跑有预算帽。提示只有 bug 报告，指令文件只走 Claude Code 自己的加载。可以不经询问跑命令。Haiku 5.5 和 Sonnet 5.5 各跑一遍。

3先分析任务结果，再分析执行成本

过期条件下，测试命令 78/80 次走到过期路径，手续 55/80，代码位置 0/84。改对之后三次都是 0。按模型、按任务分层的精确检验，过期对改对在 Holm 校正后显著（Haiku p = 2×10−28，Sonnet p = 2×10−33）。差来自测试命令和手续；代码位置没有任何一次。

任务决定这条线用不用得上。测试命令每个修复都要跑测试，两种 bug 报告都会碰上。手续那一行写描述符住在哪：宽报告写「某个 agent 描述符行为不对」，Haiku 20/20、Sonnet 19/20 走进过期目录；报告点名函数时，Haiku 4/20、Sonnet 12/20。代码位置：点名函数的报告同时点名了文件，宽报告两次工具调用之内列出包或跑测试就能拿到坏文件，没有人去翻指令文件里的旧位置。

133 次走到过期路径的跑里，第一次过期调用之前引用指令文件 2 次，打开文件 0 次。路径来自 Claude Code 加载进会话的那份。Sonnet 在测试命令上 35/40 次整段抄了文档里的命令。

4增加的工具调用发生在哪里

旧测试目录已经不在。文档里的命令收不到测试，pytest 以错误退出。测试命令过期条件 80 次里，64 次至少有一次过期路径调用没跑到测试。Claude Code 一次都没把这些调用标成错误：凡是跑了这条命令的，都把输出管进 tail 或 head，shell 报成功。Sonnet 40 次过期跑，第一次这种调用都打印了目录找不到、没有测试跑，仍记成成功。Haiku 38 次过期跑里 16 次自己用 2>/dev/null 把报文藏掉。结果：Sonnet 40 次过期跑里 19 次第一次核修复时跑的测试套件是空的；40 次改对跑里 0 次。

手续案例缺目录被标成错误更勤：Haiku 20/24，Sonnet 13/31。

工具调用只在一处能分开，而且是探索性的：Sonnet 测试命令过期 7.8 对改对 5.8，过期中位在八个任务里有七个更高；95% 区间不含零，按估计条数校正之后区间不再排除零。token 195k 对 152k，不显著。四个任务上，Sonnet 每个任务 15 次跑（5 次× 3 条件）交出同一份补丁，字节级相同，只是到那儿的工不同。删掉这一行，Sonnet 测试命令仍是 7.8，和过期一样，高于改对的 5.8。

Haiku 测试命令过期 16.0、改对 18.2、删掉 14.0。论文写同一任务里波动太大，差检测不到（过期对改对，每个任务从少 18 次到多 9 次工具调用）。手续上，宽报告平均多约两次工具调用（Haiku 2.25，Sonnet 2.0），点名函数几乎没有（0.0 和 0.25）；按任务的比较全部标成探索性。Sonnet 代码位置三次条件的调用叠在 5.3 到 5.5；Haiku 是 7.5 / 7.3 / 7.7。

5任务完成后，过期指令仍然留下

表 III 的分母是 133 次碰上：过期条件下对研究的过期路径做过操作的跑。后来有调用离开过期路径、真的跑到测试，或操作到现在的目录，记成走到目标：130/133。其中 98 次先搜过仓库。碰上之后中位再经过两次工具调用到达目标。三条轨迹没走到现在的位置就结束了。这组序列只描述绕路，不是过期行的净成本因果估计。

任务要的是改代码缺陷，不是维护文档。论文写这不能证明改文件是任务成功所必须；这是默认会做的，不是被要求维护文档时会做的。它表明日常维护里，Agent 可以绕过错误指令、交出过测试的补丁，把同一块绊脚石留给下一会话。

6你的 AGENTS.md

指令文件中的命令需要跟仓库一起维护。这项实验里，Sonnet 最终仍能完成任务，过期测试命令带来的额外工具调用却会留在执行成本里。若只看测试是否通过，就看不到这部分成本；“平均多约两次调用”仍是探索性发现。

论文测到的：改对比删掉干净。删掉之后手续仍有 20/80 走进旧目录，测试命令 Sonnet 的调用数和过期一样。论文建议维护人先核「每个修复都会跑」的那几行，例子是测试命令。路径在不在可以用脚本扫；缺了是不是错，还要人看。论文列了四条没评过的防护：Harness 若加载指令文件，可以把文件里不存在的路径标出来；Shell 开 pipefail，管进 tail 的失败命令仍失败（Agent 自己 2>/dev/null 时这条不够）；把「没有测试跑」当成失败；绕过缺失路径时，终稿写出来，并提议改那一行。

这项实验针对指令文件中已经过期的一行命令，构建命令没有单独分析。11-05 的文章比较五种脚手架下的银行操作手册，关于 AGENTS.md 的讨论属于推断，并未测试编码仓库的技能文件。两项研究都涉及说明文本，但实验对象不同。

7这篇没测到的

三个案例，指令种类、仓库、任务绑在一起，分不开。732 次来自三条过期指令的重复实验，不是独立抽样。多数任务是该行描述的代码里种下的小缺陷，更复杂的维护任务可能产生不同成本。两个模型、一家供应商、一套 harness。论文写发现按这些案例读，不要当成一般率。论文测量了触发过期指令后的成本，没有测量真实任务触发这些指令的频率，也没有估算修订或删除指令的维护成本。

平均多约两次工具调用，仅见于 Sonnet 的测试命令，属于探索性结果；Haiku 和另外两个案例检测不到。token 差不显著。删掉这一行没有把 Sonnet 测试命令的调用降到改对那一档。代码位置 0/84 只说明这些任务不需要那份文件，不能说明位置类过期指令在其他任务中没有代价。Sonnet 在点名了正确模块的 20 次手续跑里仍有 12 次搜过期目录，那是辅线。732 次没人改指令文件，前提是提示只有 bug 报告；论文写这是默认会做的，不是被要求维护文档时会做的。

引言转述 Treude and Baltes：356 个仓库的指令文件里，23.0% 标出可能过期的代码引用。本文未独立核验该项引用。构造冲突里 Agent 跟指令不跟代码，是另两篇被引，也没打开。
