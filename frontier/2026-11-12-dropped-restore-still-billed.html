忙碌时丢掉的 Restore，CAGE 4 仍按一次执行扣分

给正在执行动作的 Agent 再发一条 Restore，模拟器会丢掉这条指令，记录写成 Sleep，分数却仍扣 1 分。一篇预印本在钉死的容器里复现 CAGE Challenge 4 的两个参考防御方：关掉 KEEP 自带的忙碌检查，发布策略每局少 99.58 分；关掉 H-MARL Expert 的掩码，每局少 145.98 分。后者的已执行动作逐步不变，少的分数就是发给忙碌 Agent 的 Restore 计费。这是 CAGE 4 / CybORG 控制器上的观察，不能直接搬到别的模拟器。

1丢掉的 Restore 仍扣一分

What a CAGE 4 Score Measures 审计的是 CAGE Challenge 4：多智能体网络防御基准，排行榜按每局平均回报排名。蓝方动作带时长，Restore 占 5 步，Remove 占 3 步，Analyse 和 DeployDecoy 占 2 步。README 写 Agent「必须等当前动作完成，才会被提示再发下一条」。上一条还在跑，新指令既不排队也不报错，直接丢掉；记录把该步写成 Sleep。维护者把丢掉本身写成有意行为。Restore 是蓝方动作空间里唯一带费用的动作，调用方每交一条就扣 1 分，丢掉的也扣。论文审计的是后半句：丢掉之后仍计费。

两个带代码和检查点的参考防御方，KEEP 和 H-MARL Expert，都在自己的包装器里读忙碌标志。挑战文档里的观测表没有这个标志，七个官方包装器里三个向量包装器也不带它。官方评测脚本不写逐步回报，KEEP 那份副本默认不写记录。丢掉的指令在记录里是 Sleep，计费叠进一条总分，两边都看不见。

作者在钉死的容器里复现：KEEP 均分 −191.34（4 个抽样种子，区间 −202.61 至 −180.07），排行榜 −193.68 落在区间内；H-MARL Expert 均分 −131.34（作者评测路径 4 个种子，区间 −140.61 至 −122.08），作者报告 −129.53、独立复跑 −132.63 都落在区间内。后面关掉检查、监督投递的对照，用的是同一套 100 局配对环境种子上的单次抽样臂，KEEP 对照均分 −187.32，H-MARL 对照 −136.43，不要和上面的复现均值混比。

2模拟器怎么丢掉指令

每一步，SimulationController.step 给每个 Agent 接口收一条指令。控制器只在该 Agent 没有进行中动作时收下并执行。没有 else 分支。合法性检查在这之前已经跑过，忙碌时发出的指令不会变成 InvalidAction。忙碌的 Agent 收到成功标志为 IN_PROGRESS 的观测，描述的是上一条动作；该步记录是 Sleep，看不出丢掉了什么。

计费在奖励计算器之后，对调用方交出的指令加动作成本。作者用 tools_billing.py 核过：四条在忙碌时发出的 Restore，经控制器和文档中的 BlueFlatWrapper 都各扣 1 分，已执行动作不变。两个未加监督的 KEEP 对局里，扣分恰好等于 Restore 条数。

3关掉忙碌检查少多少分

KEEP 忙碌时策略不返回动作，翻译层写成默认的 Monitor。H-MARL 的包装器在忙碌时把动作空间掩成只剩 Sleep。作者各用一个开关关掉这道检查：KEEP 的包装器把每个 Agent 报成空闲（KEEP_BUSY）；H-MARL 关掉掩码（HMARL_BUSY）。对照都在论文表 6 的发布设置上，100 局配对环境种子。

KEEP 关掉检查后均分 −286.90，开着是 −187.32，差 99.58 分（区间 82.74 至 115.41，开着的一侧在 92/100 局里更高，无平局）。交给控制器的 Restore 从每局 77.46 条升到 180.91 条，多 103.45 条；其中 102.58 条发给忙碌 Agent，全部丢掉并计费。计费差 103.45 分（区间 98.75 至 108.22）盖住这 99.58 分；扣掉计费后的其余差 −3.87（区间 −19.49 至 10.55），区间含 0。

H-MARL 关掉掩码后均分 −282.41，开着是 −136.43，差 145.98 分（区间 142.03 至 149.97）。忙碌 Agent-步每局 1307.73，其中 1289.00 步发出了 Sleep 以外的动作；145.98 条是 Restore，全部丢掉并计费。计费差就是这 145.98 分，其余差在 100/100 局里都是 0.00，已执行动作逐步相同。对这个策略，掩码的价值就是这笔计费。

KEEP 在另外 9 个对手上关掉检查，损失 81.79 至 155.05 分，计费占其中 60.4% 到 106.9%；9 个里有 8 个，其余差的区间含 0。唯一不含 0 的是 TargetA operational：其余差 15.23（区间 4.40 至 26.59），总分差 96.67。Wrecker 上其余差最大，61.44，区间 −16.15 至 138.78，仍含 0。

发布设置上两个参考防御方相差 50.89 分（|−187.32| − |−136.43|）。按记账拆开，Restore 计费差 40.3 分（77.46 − 37.20）；原文写这只说明分数记在哪一项，不说明为什么一个防御方 Restore 更多。关掉各自的检查之后，两个策略只差 4.49 分，H-MARL 仍领先。KEEP 对照臂均分绝对值 |−187.32| 里，Restore 计费 77.46 分占 41.4%（77.1 条跑完）；H-MARL 的 |−136.43| 里，37.20 分占 27.3%。README 的奖励表没有列出这项费用。

4等到空闲再发

监督规则 O1 读真实状态，向拥有红方会话的主机所属 Agent 发 Restore，同一 Agent 两次干预至少隔 32 步。投递分两种：发出即送，不管忙不忙；或者只在空闲步询问规则，每条干预都落在空闲 Agent 上。下面表 4 的差和均分，分母是 100 局配对环境种子。

执行占比和忙碌占比来自同一条规则在 Wrecker 下的发出即送臂，不是库存对手。发出即送时，KEEP 上 60.5% 的干预能对上执行，H-MARL 上 35.8%；分母是规则发出的干预条数。空闲再发时分别是 99.0% 和 98.9%。发出即送臂里，KEEP 的 Agent 在 38.5% 的 Agent-步上忙碌，H-MARL 是 52.9%；分母是 Agent-步，含多步动作执行中的那些步。丢掉的指令还会启动规则的 32 步间隔，像监督者以为指令已经落地。

同一条规则，发出即送时相对无监督 KEEP 低 12.8 分（区间 −27.1 至 1.3，35/100 局更高），相对 H-MARL 低 24.3 分（−33.5 至 −14.3，22/100）。空闲再发时相对 KEEP 高 12.5 分（0.1 至 25.7，57/100 加 2 平，符号检验 p=0.129），相对 H-MARL 高 3.3 分（−6.2 至 13.8，43/100 加 1 平，p=0.228）。发布设置上，H-MARL 这条规则从「发出即送是净损失」变成「空闲再发测不出净损失」。规则只发 Restore，每条扣 1 分；发出即送臂比无监督 KEEP 多付 36.9 分计费，比无监督 H-MARL 多付 46.0 分，空闲再发时分别多付 25.0 和 25.4。

5你的运行位

往正在跑动作的 Agent 里塞指令，数的如果是发出去的条数，会把丢掉的也算进去。CAGE 4 的评测记录只留已执行动作，丢掉的写成 Sleep。收费如果按「调用方交出的指令」而不是「控制器收下的指令」，丢掉的 Restore 仍进总分。两边对不上时，作者建议先查有没有一条时长动作还没结束；原文没有测过这条排查路径。

官方观测不带忙碌标志时，包装器必须自己记住动作时长，或者去读原始字典。KEEP 和 H-MARL 都读了；按文档向量观测搭建的 Agent 没有这道检查，训练时还会把丢掉的指令对应的回报记到头上。作者点名这件事，没有另训一个只吃文档观测的 Agent 来定量。

单次均分还带着策略自己的抽样。库存对手上，KEEP 每局结果方差的 88.9%（区间 71.6% 至 99.8%）来自策略抽样；四次抽样里观察到的最大差是 14.9 分，原文写这不是分位数。KEEP 复现区间约 22.5 分宽。排行榜第一和第二差 4.65 分；原文写，若榜首条目带着和 KEEP 同类的抽样噪声（排行榜没有披露），这个间隔分不开两者。这些是分数怎么读的旁证，不是丢掉计费本身。

和已有几篇相邻：计划能走通，轨迹仍可能有一步执行不了；查实际状态比只看截图少误报；复现了故障，仍不能确认修复有效。这里多出来的是：丢掉的指令可以同时从记录里消失，又从计费里留下。

6这篇没测到的

全部结果在 CAGE 4 上，作者不把它推广到没有 CybORG 这份控制器的模拟器。学出来的防御方只有这两个参考方。手写规则防御方是对照，不是方案。监督结果来自脚本规则，不是人。默认每个数字是环境种子 0 到 99 的 100 局配对，另有说明的除外。

丢掉在监督臂上按干预计，因为两个发布策略都读忙碌标志；策略自己的损失靠关掉包装器检查来测，这是包装器消融，不是「从一开始就没有检查」的 Agent。作者没有在文档向量观测上跑一个 Agent。KEEP 与 H-MARL 的抽样份额不可直接并排：两套 harness 给策略种子重种的随机源不同。

训练一节把 KEEP 从零训过，有无检查的四对种子在 100 步领先、200 步起落后；续训到 2000 更新的三颗种子，一颗落进发布复现区间，两颗低 27.4 到 125.4 分。那是训练配方的选择，本文的判断不靠它。

Wrecker 是作者按 Trident 规划器模式手写的冲击型对手，不是挑战官方对手。库存对手上监督的其余差，H-MARL 一侧扣掉漏计后不再能和 0 分开。写作时没有复跑作者的容器，数字从 HTML 全文抄。
