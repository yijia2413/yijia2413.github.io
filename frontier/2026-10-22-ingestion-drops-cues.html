格式盲转换，76 篇上 docling 的 F1 是 0.150

一篇 10 月 21 日的预印本只改 Word 政策文档怎么变成模型眼前的字。76 篇、Claude Opus 4.6 上找回作者用红字或高亮标过的要求：作者那套 micro F1 0.690，docx2python 0.586，docling 0.150，纯文本 0.075。这 76 篇是从 6,462 篇里筛出、靠标记才能答的那一截。高亮和颜色是作者对自己那套表示做留一得到的负荷，原文没拆 docling 的输出里还剩什么。

176 篇上 docling 0.150

2026 年 10 月 21 日，arXiv 收到 What the Author Wrote, What the Agent Reads: Silent Cue Loss in Enterprise Document Ingestion（arXiv:2610.30026v1，cs.CL，作者 Yikai Zhao、Saurabh Pandey、Pradeep Kumar Misra，单位署 Amazon）。预印本，未经同行评审。本轮读的是 PDF 全文；实验性 HTML 页返回 200，表 1 的列与 PDF 对齐。

企业 agent 读 ingestion 交出来的 token。Word 文件本身到不了模型眼前。转换器把文字、表格、阅读顺序保住了，流水线报成功。题在问：哪些要求是作者用红字或高亮标过的。格式盲的两臂在这道题上塌掉。

这篇只论证一个判断。判断是我的，依据是论文表 1 上方面板。76 篇真实政策文档、3 次重复、1,368 次调用，同一题、同一篇，只换解析，作答模型 Claude Opus 4.6、温度 0。找回作者标过的要求，micro F1：作者那套 0.690，docx2python 0.586，docling 0.150，纯文本 0.075。篇均 macro F1 相对作者那套，docling 差 +0.578（57/76 篇作者赢），纯文本差 +0.689（62/76 篇），Holm 校正后都 < 10−4。docx2python 把字符格式保成 HTML，是测到的最强基线，仍低 0.110 个 macro F1（pHolm = 0.022）。第 4 节的留一、第 5 节的假阳性用来定位掉在哪、看不见之后怎么答，不当另一条主判断。

表 1 的 Δ 是作者那套减去对照臂的篇均 macro F1，正数表示作者那套更高。micro F1 和这篇 Δ 不是同一列，不要拿 0.690 − 0.150 = 0.540 去对 +0.578。摘要写「所有主流转换器」都丢掉视觉层；表 1 里 docx2python 已经保住格式，和那句摘要不是同一口径。下面写测到的臂。

2金标写在 OOXML 里

作者扫了 6,462 份真实 .docx 政策文档，按内容 SHA-256 命名，在 OOXML 的 run 上检测标记，不从措辞推断。整包走一遍，32.8% 带故意的红字或非白高亮，10.3% 落在带情态义务的句子上。另有 2.6% 的标记只出现在页眉、页脚、脚注或批注，正文走不到。摘要写 6,460，正文和附录 S1 写 6,462；下面用正文这个分母。

任务从这些文件里做：一篇政策里有多句写得像要求，作者用红字或高亮标了一部分，其余不标。问模型：列出作者特地标出来、提高优先级的每一条要求。金标就是 OOXML 里那组被标记的句子，没有人工判，也没有 LLM 评审。计分是集合检索（精确率、召回、F1），假阳性对着同一篇里没被标记的真实要求算，把所有要求都列出来会罚。全池未标记干扰 4,192 条；计分 76 篇里还剩多少条，原文没给。

匹配是词面、确定性的：连续四个开头实词出现在答案里，就算找回。332 条金标里只有 1 条实词不足四个，构造上匹配不到，召回上限 0.997。没被标记的干扰项没有匹配不到的。放宽到三个词或 60% 实词重合，会再接受 4.8% 未匹配对，检查后多数是另一条共用套话的要求被误配，所以保持四词规则。

入池条件：每篇至少一个已标记、至少三个未标记要求，并且已标记句不能是唯一带紧迫词的句子。这样得到 84 篇（332 条已标记，4,192 条未标记干扰），占 6,462 的约 1.3%（84/6,462，我算的）。一次运行里计分 76–79 篇：一篇要所有臂都在长度上限内产出表示，对照才成对。这 76 篇是按「靠标记才能答」挑出来的。默认作答模型是 Claude Opus 4.6，温度 0；出题和第二意见评审用别的模型家族。

没有格式，题还能做吗？作者测过，不当成默认。按文档分组的监督分类器（TF-IDF 词 1–2 元加上字符 3–5 元，逻辑回归，同一篇不进训练和测试）AUC 0.664。零样本能用的两条启发式在随机附近：紧迫词规则 0.508，句长 0.492。0.664 是格式盲方法的上界，作者这么写。

3红字的 I-9，字还在

附录 S15 给了一个入职 SOP 的解析示例，不是 76 篇计分集里的一条。示例里红字句带 WARNING 和 immediately，按入池规则这篇进不了计分集：已标记句不能是唯一带紧迫词的句子。Word 里两段挨着：

一段正常正文，把试用期加粗：试用期是雇佣的前 90 天，其间任一方可提前 5 天书面通知终止。另一段整段红字加粗：WARNING：雇员未在 3 个工作日内提交 I-9 表，将立即停薪停职。

作者的解析把加粗写成 Markdown **试用期**，红字写成 [COLOR:#FF0000]...[/COLOR]，并在块上标 CRITICAL_WARNING。附录没有给出 docling 或纯文本在这一段上的输出。字还在；run 上的颜色如果不进表示，模型就看不到作者标过哪一句。

4留一：高亮和颜色

作者在自己那套表示上做了按标记类别的留一：每次只去掉一类 span 上的标记，再重算语义角色，文档正文跨臂字节相同。高亮贡献 +0.302（Holm 后 p < 10−5），颜色 +0.262（p = 2×10−5）。加粗、斜体、等宽、删除线都在 ±0.003 以内，区间跨零。金标本身就是红字或高亮标出的要求，所以去掉加粗对这道题没有信息量，这是构造决定的。作者另外写，加粗太常见，标不出「这一条被单独点名」；单篇可以有一千多个加粗标记。这一条留一不能外推到「加粗没有用」。

原文没有报两类标记都去掉之后的 F1，也没有拆 docling、纯文本的输出里还剩没有颜色和高亮。对照臂和作者那套的差别还包括结构标签和类型角色。第 1 节的 0.150 是格式盲臂的总分，原因链停在「换了解析」；「丢掉的是高亮和颜色」是我对留一的读法。

去掉颜色，带颜色标记的文档 micro F1 从 0.699 掉到 0.214，带高亮的文档停在 0.694。去掉高亮是镜像：0.659 掉到 0.128，带颜色的文档停在 0.670。每次去掉只伤用了那一类的文档，其余最多动 0.011。

另一套题上有一条直接对着高亮的行。Microsoft OCB Word File-Fidelity 的 Highlight 特征 9 题：docx2python 1.000，作者那套 0.889，docling 和纯文本都是 0.333。这是 docling 在别人出的题上丢掉高亮的读数，n = 9，和表 1 的 F1 不是同一列。

5同一缺口，有的多列有的少列

格式盲的答案不只是少列。在 Opus 4.6 上，docling 对着同一篇里未标记的真实要求，假阳性 0.043，作者那套 0.011，原文写大约四倍。原文把这解释成看不见标记就猜。纯文本同一臂假阳性 0.005，比作者那套还低，micro F1 却只有 0.075：列得少，也找不回金标。多列还是少列，在这一列上先跟着解析臂走。docling 只在 Opus 4.6 上跑过。

换作答模型，纯文本的 micro F1 都塌在 0.007 到 0.075（论文图 2 / 表 6；论文图 2 没有 docling，因为它没在每个模型下重跑）。「几乎不答」原文写的是 Claude Sonnet 5 召回 0.09、精确率 0.96，没有写是哪一臂。

6你的文档进 agent 之前过哪一层

读完要看的是自己的运行位。政策、工单、合规问答如果先经过 Docling，或「转成纯文本再塞进上下文」，问一下：这道「作者标过哪几条」在你那一层还答不答得上。docx2python 把字符格式保成 HTML，表 1 上已经是最强基线：micro F1 0.586；篇均 macro F1 仍比作者那套低 0.110。

作者自己的修法是代码解析，零次 LLM 调用。这套表示大约是纯文本的两倍 token。40 篇上 IMPLICIT_HEADING 2,136 次、EMPHASIS 1,338 次、CRITICAL_WARNING 1,004、WARNING 452；原文写大约 62% 的角色 token 不说明作者有没有单独点名这段，分母是全部角色 token，不单是这四项。

OCB Word File-Fidelity 是另一套题：326 题、59 篇，加权断言分。修过页眉页脚、脚注、文档属性之后，作者那套总分 0.959，docx2python 0.810，docling 0.720，纯文本 0.634。38 道依赖格式的题，作者 0.816、docx2python 0.750；288 道不依赖格式的，作者 0.977、docx2python 0.818。Highlight 9 题上作者 0.889，低于 docx2python 的 1.000。不能和表 1 的 F1 做倍数。

PDF 没有 run 属性。ParseBench 表 5 的 126 条原生数字格式规则（高亮、加粗、斜体、删除线）上，作者和 pymupdf4llm 都找回 65/126 条标记；纯文本定位到 107/126 个目标，标记 0/126。能分开的只有高亮：11/18 对 4/18（McNemar p = 0.039，四类里未做 Holm）。作者的文本定位落后，75 对 82。正文另写 ParseBench 规则覆盖加粗、斜体、上标、删除线，和表 5 的四类不一致；上面用表 5。扫描件没有文字层，作者没做 OCR。

7这篇没测到的

  • 0.150 是筛过的 76 篇。6,462 篇里 84 篇入池（约 1.3%，我算的），计分 76 篇。入池就要「靠标记才能答」。整包上三分之一带故意的颜色或高亮，10.3% 落在义务句上，和这 76 篇的 F1 不是同一分母。更严模式（标记 run 自己带义务）是 5.6%，作者单独报。
  • 留一只对这道金标成立。金标是红字或高亮。加粗在 ±0.003 不能外推到别的任务。原文没报两类都去掉之后的 F1，也没拆 docling 输出。
  • 金标还没有人工标注。从 run 属性自动派生，用渲染页图做了跨模态核对，κ = 0.72。作者把人工标注写成最值钱的补。
  • 召回停在约 0.60。作者写这是题难，计分器结构上限是 0.997。绝对 micro F1 跨配置大约只稳到 ±0.08，所有主张都靠成对的篇级检验。
  • 类型角色不是六模型都成立。三个模型上重复得出。资格筛是格式免费对照文档上 macro F1 ≥ 0.80、假阳性 ≤ 0.05。Mistral Large 3 对照 0.558 / 0.133，精确率 0.480，附录 S10 另报，不进正文六模型。
  • token 大约两倍。作者写成用上下文换事实性。正文还写，渐进披露没有降低 token 成本。
  • 默认作答是 Opus 4.6。docling 没有在每个模型下重跑，论文图 2 去掉了它。表 3 把同一套抽取和渲染接到三种解析上，68 篇，那是下游管道，不是表 1 的主对照。
