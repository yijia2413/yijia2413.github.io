随机任务上，允许委派终局差 1 到 5 个点，成本 2.6 到 3.8 倍

一篇预印本在 NL2Repo 和 ProgramBench 各 30 道随机仓库构建题上，比较单独跑和允许委派。隐藏测试通过份额，同模型 Multi 终局差 1.2 到 4.7 个点；按 GPT-5.6 Sol 单价折的目录价 2.6 到 3.8 倍。等成本时单独跑不低于 Multi。ProgramBench 上表 3、表 4 是 GPT-5.6 第 2 轮（+1.2，3.2 倍）；两轮平均 +2.2，2.6 倍；第 1 轮 +3.1，2.0 倍。该轮 331 个子 Agent 里 7 个写过工作区文件。两次重复平均差约 7 个点，30 道里 10 道增益换符号。

1打开子 Agent 的那一句

预印本 When Are Parallel Subagents Effective for Coding?（Lyu、Yin、Zhang，2026-11-25）只论一件事：从两个基准各抽 30 道随机任务，自然停时，允许主 Agent 委派给 Codex 原生子 Agent，隐藏测试通过份额的终局差约 1 到 5 个百分点，按 GPT-5.6 Sol 单价折的目录价 2.6 到 3.8 倍；按同一美元预算读，单独跑不低于 Multi。NL2Repo 上同模型 Multi 的自助区间含 0。后面几节写难任务上多出来的检查、Claude Code 小规模复现，不另立判断。

仓库构建和修 issue 不同。作者写 SWE-bench 一类通常改几行，可并行的块少；NL2Repo 和 ProgramBench 要按规格重建整个程序。NL2Repo 给书面规格和用法示例。ProgramBench 另外给一份可执行参考程序，Agent 可以对同一输入比输出。分是活跃隐藏测试通过份额，不是官方 resolved：作者写难任务上 resolved 几乎全是 0。ProgramBench 的活跃测试是任务分片减去官方忽略表；NL2Repo 是整份隐藏套件。跑之前，作者的计分器和官方 ProgramBench 评测器在 30 道参考程序上一致。

主设置是 Codex。RQ1、RQ2 用 0.147，主 Agent 和 Sol 子 Agent 推理档 xhigh，Luna 子 Agent 用当时默认档。每条跑在 4 小时封顶内自然停，提示里没有截止日期。单独跑（Single）不启动子 Agent。并行（Multi）在题面后加一句许可：独立部分可以交给原生子 Agent，数量、切分、合并、核验由主 Agent 自己定，不强制委派。同一套子 Agent 用 Sol，弱一档用 Luna。作者写：每一个 Multi 跑都委派了，中位 7 到 10 个，随基准和变体变。目录价：Sol 每百万 token 输入 4 美元、缓存输入 0.4、输出 20；Luna 是 0.2、0.02、1.2。GPT-6 Sol 和 GPT-6.1 Sol 按 GPT-5.6 Sol 的单价计，跨代比的是 token 用量。

2随机 30 加 30 道上的终局

随机集固定抽签顺序，每个基准 10 易、10 中、10 难。NL2Repo 一道难任务 pytorch-grad-cam 的核验器跑不起来，换成下一道 cookiecutter。NL2Repo：Single 和弱子 Agent 每题 3 次，同模型子 Agent 每题 1 次。ProgramBench、GPT-5.6 Sol：每个设置每题 2 次，但下面表 3、表 4 的 ProgramBench 列只展示第 2 轮。分数是任务等权平均。原文附录 C：两轮平均，同模型 Multi 比两次 Single 高 2.2 个点，成本 2.6 倍，30 道里 22 正 8 负；第 1 轮单独是 +3.1 个点、2.0 倍；第 2 轮就是表里的 +1.2 个点、3.2 倍。第 1 轮 15 道题的子 Agent 推理档是 low，其余和第 2 轮是 xhigh。GPT-6、GPT-6.1 各一跑。

ProgramBench 随机题上，允许委派不等于并行写模块。附录 C：第 2 轮 30 条都委派，合计 331 个子 Agent；7 个写过任何工作区文件，2 个写了产品文件，都在 jsonschema。作者写这一轮子 Agent 只做探测，和 RQ2 难任务上一样。NL2Repo 上子 Agent 有没有写代码，原文没给，不往那边推。

NL2Repo 上，按题配对、自助 95% 区间：同模型 Multi 相对 Single 是 +2.9（−3.3 到 +8.4），成本 3.83 倍（3.26 到 4.46）；弱子 Agent 是 −2.4（−5.5 到 +0.4），成本 1.70 倍（1.50 到 1.94）。主 Agent 自己在弱子 Agent 设置里已经是 Single 成本的 1.6 倍，同模型设置里 1.3 倍。Luna 子 Agent 只占该设置总成本的 3%，Sol 子 Agent 占 67%。

Claude Code 2.1.283、effort high、Opus 5.5：每个基准 10 道随机题，每格一跑。ProgramBench 上 Multi 平均 95.5 对 Single 90.7，+4.7 个点，成本 3.1 倍。4 到 13 个子 Agent 出现在 delta、solar、jsonschema、lightningcss；其中三道 Multi 高 12.6 到 18.6 个点，成本 2.6 到 5.2 倍，jsonschema 两边都高于 99。另外六道最多起两个子 Agent，两边差在 2 个点以内。NL2Repo 上每次都委派，Multi 没有更高：Single / 同模型 Multi / Haiku 4.5 子 Agent 平均 94.4、90.5、88.0，成本 0.9 到 1.4 倍。差额来自一道题，两个并行跑都漏了测试会 import 的助手代码；其余九道三个平均在 94.0、94.5、93.4。作者写：一格一跑，只在差额明显超过第 3 节的重复波动时才当结果读。Grok 4.6 和 MiniMax-M3 没有随机题上的自然停对照。

3等时间能领先，等成本不领先

工作区每 5 分钟存一份，每份都计分。某时刻的分是当时最后一份快照；终局是最后一份。时间是 Agent 工作时间。成本把主 Agent 和子 Agent 的每次请求按目录价加总。某美元预算上的分，是累计成本刚超过该预算之前最后一份快照。

NL2Repo 的隐藏测试按模块分开查。作者写：子 Agent 并行写出的模块可以早过测试。表 3：5 分钟时同模型 Multi 47.2、Single 16.9；20 分钟 70.1 对 64.6。原文没报 NL2Repo 上有多少子 Agent 写了文件。ProgramBench 的测试跑整程序，要等主 Agent 写出把模块接起来的那个文件。这个文件的中位出现时间，Multi 11.6 分钟，Single 9.0 分钟。ProgramBench 上 20 分钟时，GPT-5.6 第 2 轮 Multi 68.9，Single 69.4，并不领先。该轮子 Agent 基本不写代码，见第 2 节。

按成本读，同模型 Multi 要花到大约 Single 平均成本的四倍，才追上；弱子 Agent 几乎全程落后。附录 C：NL2Repo 上约 1 到 5 美元每个预算 Single 都高；低于 0.9 美元时弱子 Agent 略领先。ProgramBench 上弱子 Agent 每个预算都低，5 美元之后大约低 2 个点；2 美元时 36.2 对 62.6。同模型 Multi 在每个预算上到约 23 美元都落后。表 3 里 2 美元、3 美元两行，同模型 Multi 在 ProgramBench 上是 0.0 和 0.0；原文表里只有这两个 0.0，没有写原因。作者写：等成本时，两个基准上 Multi 都不领先 Single。

同一设置两次跑，平均绝对差大于设置之间的平均差。GPT-5.6 Sol、ProgramBench 30 道：Single 两次平均差 7.1 个点，中位 2.6；同模型 Multi 6.5 个点。30 道里 10 道，两次对比的增益换了符号。附录 C 举例：quinn 两轮是 +1.0 和 +28.4，ripsecrets 是 +2.6 和 −15.7。作者写因此不把任何单题增益当结果报。Finding 1 原文：随机任务上，子 Agent 用数倍成本换终局小幅提高；等成本时单独跑打平或更好。ProgramBench 上难任务的中位增益大于易和中。

ProgramBench 10 道难任务的中位增益，三代是 +2.0、+5.6、+8.4；20 道易和中是 +1.7、+0.6、+1.0。这是图 3 注的中位数，上面的单题警告仍然适用。NL2Repo 反过来：难任务中位 +1.1，其余 +3.3。作者写可能因为 NL2Repo 没有参考程序，子 Agent 多出来的检查靠这一份。

4难任务上多出来的检查

这一节是辅线，解释 ProgramBench 难任务上那几分从哪来，不改第 2 节的判断。RQ2 用 16 道 ProgramBench-Hard，含 RQ1 的难任务。自检用两条轨迹量：自然停之前的分钟数，以及同一输入上对参考程序和自己程序各跑一次的命令数（差测）。差测先按跑平均，再按题取中位。

表抄原文表 5。分是隐藏测试份额，差是百分点。时间和成本：Single 列是均值，Multi 和 Probe 是相对 Single 的百分变化，分母是两边都计分的题。GPT-5.6 的 Probe 在 16 道里计了 15 道（缺 delta），所以 +6.7 和 Multi 的 +8.8 不是同一题集。GPT-6 的 Multi 计了 15 道。难任务上 Single 基线是三次平均，Multi 和 Probe 各两次。GPT-5.6 上按题中位，Probe +1.3、Multi +4.9。附录 D 写 gomplate 第一轮停在 Single 一半分数，去掉这道后 Probe 那一格是 +8.4。Finding 2 原文：有参考程序时，一句让 GPT-5.6 Sol 的单独跑先探接口，用一小部分成本收回大部分增益。这是作者的结论。GPT-6.1 上单独跑已经更长，Probe 均值 −1.5。atlas 这一道：GPT-5.6 的 Single 47%，Multi 77%，Probe 75%；GPT-6.1 的 Single 88%，子 Agent 再加 2 个点。作者手读 GPT-5.6 在 7 道题上的全部 17 条 Single 跑，每一条都是一次检查刚过就停。skeema 上自己的测试没连数据库；gittype 上把错误流并进标准输出再比。Probe 句同时改变了检查和运行时长。

RQ3 把自然停拿掉。Single-Extended 接到最多 20 小时；Multi-Extended 提示里写 token 和 API 成本完全不计，最多 4 小时，delta 上最长一条 8.5 小时。作者写：等时间 Multi 领先；等成本时除非改坏耦合代码，否则晚些时候才超过 Single。清空对话的新会话起步更快；delta 上 GPT-6.1 的新会话链终局也明显更高。剩下的差距和模块划分有关：Single 几乎写在一个文件里时，等成本 Multi 仍明显更高。这三道是选的，不是抽的。Multi-Extended 另外要求按模块切、每块自测；delta 上给单独跑同一句、不起子 Agent，这句话最多解释 4 小时领先的四分之一，另外两道没有这个对照。作者把 delta 上「等成本 Multi-Extended 明显高于 Single」写成案例，因为每设置一跑。表 7 上 GPT-5.6 扩展跑的终局成本，delta 是 Single-Extended 260 美元对 Multi-Extended 1,201 美元。

5你的运行位

Codex 或 Claude Code 里用一句话允许委派，账单按目录价走，不管程序有没有变好。这篇在随机仓库构建题上：同模型 Multi 终局差 1.2 到 4.7 个点，按 5.6 单价折的目录价 2.6 到 3.8 倍；弱一档子 Agent 两边都低于单独跑。ProgramBench 表列是第 2 轮；两轮平均 +2.2、2.6 倍。该轮 331 个子 Agent 里 7 个写过工作区。等墙钟，NL2Repo 上 Multi 可以早亮；等美元，单独跑打平或更好。GPT-5.6 在 ProgramBench 上两次重复平均差 7.1 个点，大于设置之间的平均差，30 道里 10 道增益换符号。NL2Repo 同模型差 +2.9，自助区间 −3.3 到 +8.4。默认打开之前，先看验收是墙钟还是美元，以及同一题再跑一次会不会把那 1 到 5 个点吃掉。

难任务、旁边有一份可执行参考时，Finding 2 把 GPT-5.6 上「探一句收回大部分增益」写成作者结论。表 5 里这一格均值 +6.7（15 道，缺 delta）对 Multi 的 +8.8（16 道）；按题中位是 +1.3 对 +4.9。成本上 Multi 比 Single 多约 275%，Probe 多约 50%，比的是整个设置的总成本。GPT-6.1 的单独跑已经更长，同一句均值不再加分。没有参考程序的 NL2Repo 上，难任务的中位增益并不更大。运行位如果已经强制长跑、强制自测、强制按文件拆模块，这篇没有估计再加委派还能剩多少。

技能记录里如果把「开子 Agent」写成默认加速，对一下这篇 Finding 1 的分母：两个基准各 30 道随机题，自然停，隐藏测试份额，按 5.6 单价的目录价。Claude 的 +4.7 挂在 Opus 5.5、每基准 10 道、一格一跑，不要和 Codex 表 4 的第 2 轮放进同一个倍数。

6这篇没测到的

  • 多数对比每设置 1 到 3 跑。ProgramBench 上两次重复平均差约 7 个点。Claude 复现每格一跑。
  • RQ2 的探一句同时拉长时间和成本。RQ3 的并行扩展设置还要求按模块切和自测；模块到分数的边是观察，图 1 没有估计边的大小。
  • RQ3 的题是选的，作者写只认机制、不估计有多常见。自检度量靠参考程序，多数项目没有。
  • 只覆盖闭源模型、三个产品、整程序任务、单次运行里花掉的计算。推理档按跑类型钉死，没有扫描。
  • 差测是否覆盖了某功能，靠命令文本的固定规则。42 条跑和 294 份快照重计过分；附录 B 列出挂起测试、分页器、覆盖参考程序路径等缺陷。
  • Grok 4.6、MiniMax-M3 在 Claude Code 的同一句许可下，delta 和 solar 上一次都没委派。dsh 上探一句没有把 GPT-5.6 的分抬起来。这些不进第 2 节的判断。
