按无技能分关技能，回放涨 2.92 个点，留出含 0

一篇预印本审计 SkillsBench 的公开跑次：7,554 条配对试验、1,421 个（配置，任务）格子。后续工作按任务增益关技能。无技能分低于 0.8 才加载，相对「总是加载」，同一日志回放 +2.92 个百分点（任务自助 95% 区间 +1.93 到 +4.02）；把条件标签打乱、技能效应清零后仍 +4.5；没用过的留出试验 +0.12（−0.67 到 +0.93）。17 个任务净增益为负，FDR 10% 下 0 个显著；169 / 1,421 个格子 Δ<0，算术上 58% 的格子不可能出现下降。

1关技能用的那一列

预印本 What Does Skill Lift Actually Measure?（Zhang、Long，2026-11-25）审计 SkillsBench 的冻结快照。本篇只论一件事：用无技能分决定这次要不要加载技能，同一批日志里看起来涨了，没用过的留出试验区间含 0。后面几节是负格子从哪来、最大正增益里有没有评分缝，不另立判断。

SkillsBench 原文（Li 等，arXiv:2602.12670v4）在 87 道容器题、18 个「模型–框架」配置上，有无人工技能对照，任务等权过测率从 33.9% 到 50.5%，+16.6 个百分点，87 道里 13 道净下降。后来的工作按任务增益关技能、压包、检索、测覆盖、改内容。这篇审计的快照不是基准论文最后那一子集：两份公开导出合成 1,421 个配对格子。格子等权平均分：无技能 30.06%，有技能 48.75%；摘要写成全套平均增益 18.7。格子等权，不是任务等权。

一份是 2026-06-15 的早期清单 paper_v1_manifest.json：2,830 行，7 个配置，Claude Code、Codex、Gemini CLI；上游按模型、条件、任务名留最早三次有限分、未超时、还留日志的跑。一份是 2026-06-08 的榜单导出 selected_trials.csv：6,590 行、22 个配置，其中 19 个是 OpenHands。两份原始行 9,420；去掉无有限分 1,029、格子只有一侧 760、任务不在审计仓库 77，留下 7,554 条配对跑。分恰好 0 / 恰好 1 / 部分分：4,356 / 2,835 / 363。配置 28 个（第一批 7、第二批 21）。83 / 87 道题至少有一个配对格子。两边都三次的格子 907；至少一侧只有一次 219。

格子里 r0、r1 是无技能、有技能的平均分，Δ = r1 − r0。每个格子每侧最多三次。作者写：后续方法经常直接用观察到的任务增益做关停。

2负格子从哪来

快照里 11.9% 的格子（169 / 1,421）Δ<0，17 道题净增益为负。823 个格子无技能三次全挂（r0 = 0），算术上不可能下降。259 个格子无技能全过（r0 = 1），不可能正增益；有技能三次里挂一次，看起来就是掉 33 个百分点。能出现下降的只有基线为正的 598 个格子。摘要写算术上 58% 的格子不可能出现下降：823 / 1,421 ≈ 57.9%。

格子内打乱条件标签、每侧次数固定，100,000 次置换加一校正，83 道可观察题做双侧蒙特卡洛 p，FDR 10%（Benjamini–Hochberg）。26 道显著，全是正增益。17 道净负里，校正前最小双侧 p 是 0.15（单侧 0.075）。最负的一道 exam-block-sequencing：11 格均值 −13.6 个百分点，3 个下降、1 个上升、7 个打平，p = 0.30。作者写：不显著不等于没有伤害。零技能效应下，置换期望 327.7 个负格子（中心 95% 范围 302–353）、332.5 个正格子；实际 169 个负、547 个正。作者写：许多有益技能加少数有害技能，总负格子也会低于 327.7，所以 169 低于期望不能证明技能无害。

至少每侧两次的 1,202 个格子，每次随机留出每侧一条。约 279 个决策集 r0 ≥ 0.8 的格子，决策试验均值 Δ = −16.1 个百分点，留出回到 −0.5（95% 区间 −4.0 到 +3.1）。约 123 个决策集 Δ<0 的格子，决策试验 −56.2，留出 −9.9（−16.8 到 −2.7），26% 仍下降、18% 上升。作者写：表观损失格子平均不是纯噪声；−9.9 对 −56.2 不要直接读成真实伤害比例。

3回放涨、留出含 0

基线门槛：只在 r0 < 0.8 时加载技能。作者写这是对 Wang 等（arXiv:2610.32322）用独立探针、阈值 0.8 再加跨模型过滤的粗近似。对照是「总是加载技能」。三种评法：同一日志回放；格子内打乱标签再回放；至少每侧两次的 1,202 格里，决策试验做决定，留出试验记分。

r0 同时进门槛、进回放得分、又来自最多三次试验。作者写这是同一噪声项耦合。风险森林预测 Δ<0 的 ROC-AUC，正文写 0.878，表 VI 格子折 17 特征是 0.879±0.005。只看指示量 r0>0 已经是 0.829，因为它直接排除了不可能下降的 58% 零基线格子。限制在 r0>0 后，指示量 AUC 0.500，17 特征森林在格子折上 0.646±0.015，任务折上 0.524±0.027。表 VI 森林行是 8 个随机种子的均值±标准差，作者写这反映拟合波动，不是抽样不确定度。

4审计留下的三道评分缝

源码对照提示、参考解、评分脚本和技能包。审计留下三道「指令–评分缺口」：两道用官方评分器做了受控跑，一道只做源码审。作者写若干最大增益落在这类缺口上。先排除了两个候选：weighted-gdp-calc 的评分脚本会先跑 ssconvert，没有缓存也能读到计算值；sec-financial-report 的容差和四舍五入助手脚本不构成未声明单位。另外两道最高增益任务没审：llm-prefix-cache-replay（0 到 97.4%）和 dapt-intrusion-detection（7.7 到 78.8%）。

地震目录上球面大圆 3,552.98 km、Web Mercator 4,152.56 km、EPSG:4087 3,878.27 km 指向同一事件；只有 EPSG:4087 过全部八条断言，另外两个距离检查失败、得 0。作者写受控跑证明漏写的要求会改评分，没有量化观察到的技能增益有多少来自这条缝。

四道题旁有职位名目录，例如 senior-data-engineer：四个目录合计 53 个文件、约 584 KiB，其中九个文件写着 “TODO: Implement actual functionality”。四道占位题增益在 −6.5 到 +14.2 个百分点。上游从 190 条 OpenHands 轨迹抽出第一轮系统提示：184 条有技能试验里，155 条在 1 到 7 个任务技能前面列了 48 个内置技能（重建目录文本 15,449 字符，没有 token 数），任务技能只占目录条目 2%–13%；6 条无技能试验里 4 条也出现这 48 个。作者写：无技能条件里，内置技能出现在部分试验。榜单官方列上三个模型的原生 CLI 平均增益 20.9 个百分点，OpenHands 15.3；这是榜单三对，不是 1,421 格子快照。作者写三对不够把差额归因到目录稀释。

5你的运行位

技能记录里如果用「这题无技能已经够高」做卸载，检查决策分和验收分是不是同一批最多三次的试验。这篇冻结快照、固定策略上，基线门槛相对总是加载：全表 1,421 格回放 +2.92 个百分点，同一批 1,202 格的决策集回放 +3.7，留出 +0.12（−0.67 到 +0.93）。打乱标签后全表回放仍 +4.5。作者把回放增益解释为 r0 同时进门槛和得分，均值回归会被吃进去。结论只覆盖固定策略和冻结快照；作者写不排除用独立探针集训出门控。

按任务 Δ 关技能，先看格子能不能为负：r0 = 0 的 823 格算术上 Δ 不能为负。169 个负格子、17 道净负题，在 83 道、FDR 10% 下没有一道显著为负。作者写每侧三次时，真实损失要超过约 24 个百分点才有 80% 检出力。作者建议：不要只用三次试验的格子差做退休决定。

看这快照的格子等权 +18.7 时，留下的三道评分缺口占格子 4%、描述性占累计增益 18%。题面没写、只有技能包写了的评分约定，会进这一列。SkillsBench 原文的 +16.6 是任务等权，上面的 18% 不算在那一列。

6这篇没测到的

  • 冻结快照不是基准论文最后子集；11% 原始行没有有限分；第二份导出早于最终子集，四个仓库任务没有配对格子。
  • 留出评分每格只用一对试验，并丢掉 219 个试验少的格子。门槛和森林超参是在能看见留出试验的阶段定的，作者写这会让留出结果偏乐观。
  • 格子内置换假定试验可交换。超时：第二份导出有技能 8.99%（219 / 2,436），无技能 7.12%（168 / 2,358），比 1.26（任务自助 1.03–1.56）。作者没测交互步和计算步，不解释原因。
  • 洪水那道缺口只有源码审。算法路径不同的三道（MIP、Python 距离回调、有限时域 MPC）作者写成策略差异，没有测这些路径是否更差。
  • 维护者 2,333 条试验里 58 条标异常加载或无技能泄漏、7 条疑评分泄漏；33 条涉及快照外两个模型，其余对不上导出表。作者没有报本样本污染率。
  • 结构标记是看见跑次之后编的。Wang 等的 0.8 来自独立探针，这篇门槛直接用格子里的 r0。
