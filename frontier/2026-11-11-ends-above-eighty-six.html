AGENTS.md 写下的指令，Agent 遵守了多少

仓库里的指令，哪些会落到 Agent 的提交上？一篇预印本逐条检查 AGENTS.md / CLAUDE.md 中能用脚本核验的规则。在至少有一次适用提交的 2,053 条指令里，91.7% 要么每次都遵守，要么一次也不遵守。把门槛提高到至少 3 次或 5 次适用提交，这一比例仍有 87.3% 和 86.2%。这是提交产物上的观察，不能直接证明指令本身的效果。

1指令遵从率集中在两个端点

编码 Agent 通常在会话开始时读取仓库根目录的上下文文件。论文把这类文件叫 agent context files（ACF）：AGENTS.md、CLAUDE.md、copilot-instructions.md。作者问的是单条指令有没有落到提交上，不把整份文件当成一次处理。

依据论文第 4.3.2–4.3.3 节（HTML）。能核到至少一次适用提交的 2,053 条指令里，两端合计 91.7%；门槛收到至少 3 次适用提交是 87.3%（n = 1,144），至少 5 次是 86.2%（n = 819）。全样本才拆得出 1,116 条（54.4%）每次都跟、766 条（37.3%）一次都不跟、171 条（8.3%）夹在中间。分母是指令条数，不是 14,902 条候选，也不是 6,541 次提交。均值 59.8% 是这 2,053 条各自遵从率再平均；中位数 100%。遵从是提交产物上的脚本判定，看不到推理，也没有「没有这条指令」的对照。

论文把遵从率按指令汇总，一条指令无论碰上 1 次还是几十次提交，只贡献一个率。两端合计在三档门槛下都超过 86%；54.4% 和 37.3% 则仅在全样本中分别报告，不能推广到另外两档。

2哪些指令能够核验到提交

ACF 来自先前按官方文件名从 GitHub 挖的语料，只留 Copilot、Claude Code、OpenAI Codex 三个 Agent。上下文快照按内容去重：676 个快照、10,763 次提交、307 个仓库。提交来自 AIDev，只用严格 Agent 子集：机器人账号或明确的作者元数据。两个集合按仓库对齐之后，分析集是 6,541 次提交、268 个仓库。表 1：改源码 4,067，改测试 1,381，改文档 1,072；中位每次改 1 个文件，均值 3.95。分类用的是这 676 个快照去掉空的和格式坏的之后剩下的 621 个。

指令要同时过三道门：写在文件里（显式）、规定一件改动时能做的事（可执行）、提交产物上能核（可观察）。「跑一遍 linter」过前两道，过不了第三道：改完的文件看不出跑过没有。标注器是本地 Qwen 3.5 9B。621 个快照抽出 14,902 条候选，平均每个快照 24.0 条。显式 10,324（69.3%），再加可执行 8,726（58.6%），再加可观察 6,552（44.0%）。论文写可观察这一层是上限：84 个快照、2,113 条确认指令上，可观察标签准确率 85.0%，分歧里九成以上是模型多算进去。

6,552 条里，4,123 条（62.9%）生出了测量脚本。生成器另采十个脚本、十个夹具，过最低正确门槛，还要有独立脚本互相印证。抽查 94 条被接受的脚本，67 条（71.3%）实现了对上行为描述；常见错法是把 ACF 里的例子文件名写成硬条件，脚本比原文更严。2,569 / 4,123（62.3%）在没碰到相关文件时仍返回 True，所以后面加了适用过滤。4,123 条里只有 2,053 条（49.8%）至少碰上一次适用提交，共 18,594 对指令–提交。从 6,552 往下是 31.3%；从 14,902 候选往下是 13.8%。

3部分遵守的指令占多少

2,053 条可核指令，每条一个遵从率：适用提交里脚本判跟的比例。均值 59.8%，中位数 100%。1,116 条（54.4%）全是 100%，766 条（37.3%）全是 0%，171 条（8.3%）落在开区间里。两端合计 1,882 条，91.7%。

中位每条只有 3 次适用提交；540 条（26.3%）恰好 1 次，那一条的率只能是 0 或 100。论文把门槛收到至少 3 次（n = 1,144）和至少 5 次（n = 819）。两端占比从 91.7% 降到 87.3%、再降到 86.2%；中间从 8.3% 升到 12.7%、13.8%。最严一档，多半指令仍是每次都跟或一次都不跟。

全样本两端 1,882 是 1,116 + 766，百分比 91.7%、8.3% 原文已写。≥3 和 ≥5 原文只给两端合计和中间占比，没有再拆全跟 / 从不，表里也不拆。论文写：非遵从集中在从不跟的那些指令上，抽几条已经会跟的规则，看不住其余 37.3%。

数字还要往乐观一侧读。适用过滤漏过去的指令–提交对会记成跟，不会记成不跟；报告的非遵从是下限。抽查 94 条被接受的脚本里，67 条实现对上，27 条没有忠实实现指令；最常见的错法是把 ACF 里的例子写成硬条件，使脚本偏严，实现 bug 原文写成 comparatively rare。两股偏差方向相反，论文没有给出净值。

4类别和 Agent

不同指令类别与 Agent 之间也有差异。Implementation Details 比 Testing 跟得更勤，这一对在至少 3 次、至少 5 次门槛下仍显著。Development Process 全样本均值 34.0%、中位数 0；收到至少 3 次之后，它和另外三类的成对差异不再过校正。Copilot 可核 1,137 条，均值 66.0%；Claude Code 799 条，52.2%。Copilot 对 Claude Code 的差距在三个门槛下都显著，Cliff’s δ 在 0.12 到 0.15。论文没按类别配平 Agent，写成关联，不写成身份因果。这些类别均值与两个端点的占比，衡量的指标不同。

5你的 AGENTS.md

上下文文件需要逐条检查。只抽查几条一直被遵守的规则，无法发现全样本中一次也未被遵守的 37.3%。论文建议一条指令只写一个能从产物核验的行为，使用祈使句，减少“必要时”“合适时”这类限定。对流程约定，作者倾向用 hook、分支保护和 CI 执行；这仍是实践建议，Development Process 类别的成对差异没有通过灵敏度分析。

我的判断是，AGENTS.md 中写下的规则还需要对应产物检查。仅修改措辞，无法由这项观察性研究保证遵守率改善。相关的三篇文章分别讨论了过期测试命令、同一条政策的不同写法，以及压缩后保留的规则。这里补充的是逐条指令与提交产物之间的关系，论文没有测试具体仓库的改写方案。

6这篇没测到的

没有「删掉这条指令」的对照，跟也可能是生态默认。脚本吃的是改动文件的全文，不是行级 diff：文件里原先就违规，会算到这次提交头上；原先就合规，可能盖住这次引入的违规。遵从是二元，没有部分跟的等级。适用过滤按扩展名和惯用文件名，碰到同类文件就算适用。

只覆盖三个 Agent、公开 GitHub、严格归属子集。原文写有的 Agent 用机器人账号直接提交，Claude Code 常出现在共同作者里，GitHub Copilot 可能靠分支名这类间接信号；严格子集「likely imbalanced」，没有给出验证过的精度。可观察标签交叉模型一致率 76.1%，校验是单人。脚本生成温度 0.8。生成模型是 Qwen2.5-Coder-14B-Instruct，标注是 Qwen 3.5 9B，都是本地开源权重，换模型漏斗会动。时间切片随 ACF 惯例一起过期。

写作时未能读取 HTML 所列的复制包，无法检查脚本和逐条判定。TOSEM 页眉是模板。主研究的协调率、工具调用次数、任务通过率这篇都没测。
