给下一道未知任务的记忆，该留路径和检查命令

编码 Agent 连做同一仓库的下一道题时，上一道题该留下什么？一篇预印本在 Qwen3.8-27B-FP8、linked 边界上，把当前轨迹切成七段当记忆，分别拿掉一段，看下一道未知任务会多走几步。删掉命令或读过的仓库内容，中位会多 2 步和 1 步；删掉推理正文或 diff 正文，步数不增。按这个结果写成的记忆，在 ChainSWE 测试半、同一 27B 上，演员未训练时过测率 21.0% → 23.4%、步少 10%；再训练该模型后过测率 25.7%、步少 17%，含写记忆调用的总 token 少 11%。17% 里含训练本身让演员更省步的部分，原文没拆开。稿件推断：跨任务记忆该先留仓库位置和可执行检查。

1下一道题要锚点

CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation 盯的是连续修仓库：一道题做完，工作树留给下一道，轨迹本身丢掉。下一道题是什么，写记忆的时候还不知道。作者把这种记忆叫 CoReMem，把该留下的东西叫锚点：仓库里的位置，以及能原样再跑的检查。

原文图 1 用 flake8-simplify 做示意，演员是训练后的。上一道题结束时写下 WHERE 和 VERIFY，下一道题在第 1 步和第 6 步用上它们，少做开头那一轮翻仓库。图注写明步数是示意，不是表 1 的实测。

摘要里的主结果对着 ChainSWE、Qwen3.8-27B-FP8：相对「同一套未训练的发出命令模型、不写记忆」，过测率 21.0% → 25.7%，步少 17%，含写记忆模块调用的 cache-aware 总 token 少 11%。原文把发出命令的模型叫 actor，下文写成演员模型。测试半是 48 条链、96 个任务边界，过测率的分母是这 96 道下一题。表 1 同一行：步从 35.1 到 29.2，总 token 从 32.2K 到 28.5K，写记忆那一侧 1.9K。括号里是会话中位数，正文比较用均值。17% 和 +4.7 个点把记忆内容和训练捆在一起：附录 E 里同一 27B 在没有记忆的 Verified 上，训练后也少 7% 步（28.3 → 26.2）。表 1 没有「不写记忆、训练后」这一行，原文正文也没报 21.0% → 25.7% 的区间。未训练演员加 ReasoningBank 的过测率是 25.2%（+20%），步只少 2%，总 token 高 110%；过测率和训练后 CoReMem 的 25.7% 接近，CoReMem 的差在步和 token。

2怎么量一段值多少

一条轨迹按角色切成七段：演员自己的推理、发出的命令、读到的仓库内容、测试输出、留下的 diff、结局、草稿文件。估值在 Qwen3.8-27B-FP8、linked 边界上做：下一道题从上一道留下的树起步，整段轨迹当记忆跑一遍，再拿掉其中一段跑一遍。unlinked 边界和其他演员没有做分段删除。中位步差记成 ν，中位演员 token 差记成 κ。附录 I 写这些读数默认在 linked 边界上，除非另行说明。测试半 linked 是 54 / 96。命令段 56 / 27 条边界上删了会多走，BH 校正后 p* = .0070，中位多 2 步；读过的仓库内容 52 / 34，p* = .0302，中位多 1 步。两对数加起来都超过 54，原文没写这些计数来自哪个划分、几次重放。

表 8 的分数对是「这段帮了下一题 / 这段害了下一题」：帮了 = 删了会多走，害了 = 删了会少走。推理正文删了不多走步（34 / 45），还省 1.14K token（未校正 p = .023）。diff 正文同样不多走步（47 / 44），省 0.94K token（未校正 p = .021）。没检出步差不等于差为零，原文没给这两格的区间。测试命令带退出码，比贴全文输出中位少 1 步（53 / 30，p* = .045）；这格比的是缩短形式，不是整段删除。草稿路径里 38% 在 /tmp 下，原文写到下一条命令时已经没了，清单本身不省步（36 / 48）。27B 不写记忆的步是均值 35.1、中位 26.0，中位 +2 / +1 步对着这个量级。

拼起来的记忆，在 linked 边界上保住整段轨迹的中位步收益，2 步里的 2 步，体积是 1,056 对 17,320 字符，约 6%。比值区间 [0.50, 2.00]，下界恰为作者设的 0.50 保留门槛。作者把位置和检查叫锚点：带行号的路径、代码名、测试节点 id、命令里的非开关词。短于 6 个字符的、纯常见英文或 shell 词、以及 setup.py / conftest.py / /tmp 这类脚手架，匹配时丢掉。附录 L 把记忆限制在至多 10 行、合计 1,200 字符。匹配器是作者自己写的字符串规则，和训练里给「用了记忆」的门控是同一套（附录 K，式 6）。

表 2 在 27B 未训练演员、测试半上数下一道题实际用了多少锚点。一条锚点算「用了」，当它只出现在记忆里，并且出现在下一道题会话的某条消息中。每条记忆用上的锚点，CoReMem 未训练是 2.24 [1.67, 2.87]，MemOp 是 2.06 [1.59, 2.51]，区间重叠。每千字符用上的锚点，CoReMem 1.32 [1.00, 1.68]，MemOp 0.92 [0.72, 1.11]，ReasoningBank 0.19 [0.14, 0.24]，Mem0 0.14 [0.08, 0.21]。后一列奖励短记忆。括号是 48 条测试链上的 95% 区间。

3六套模型上步数怎么变

ChainSWE 一共 100 条链，按仓库切开、不看结果：训练半 52 条链、97 个边界；测试半 48 条链、96 个边界。同一仓库不会两边都出现。测试边界里，下一题的 gold / 测试补丁碰到的文件，和前面 gold 补丁改过的文件有重叠，记成 linked，54 个；其余 42 个 unlinked。主框架是 mini-swe-agent，窗口 98K。开源权重三套也做了训练：Qwen3.5-9B、Qwen3.8-27B-FP8、Gemma-4-31B；接口三套只跑未训练记忆：Claude Opus 5.5、GPT-5.6 Luna、DeepSeek-V4-Flash。27B 步数上限 100，其余 200；接口模型 200。

对照有：不写记忆、注入更早任务的最近一段全文、Mem0、MemOp、ReasoningBank。过测率是会话结束时隐藏测试在工作树上通过的下一题份额。一步是一次助手回合、一条命令。token 按 cache-aware 计，演员调用和写记忆模块调用分开，总 token 是两者之和。每一行是多次重放的均值：未训练 9B 12 次，27B 6 到 7 次，DeepSeek 6 次，Gemma 和 Luna 3 次，Opus 1 次。和「不写记忆」的差，用 48 条测试链上的配对 cluster bootstrap；原文把 95% 区间不含 0 叫显著。

第 4.2 节写：训练后相对不写记忆，三套开源权重步都少，最多少 26%；总 token 少 9% 到 19%；过测率高 22% 到 27%；每千总 token 的过测率高 38% 到 46%，平均 41%。41% 是三个相对变化的平均，分母是各模型自己的「不写记忆」每千 token 过测率，不要和 21.0% → 25.7% 那 4.7 个百分点放进同一个倍数。

演员冻结、只换记忆时，六套模型步都少。原文写其中三套显著少 9% 到 13%；过测率五套升高，Opus 不变（38.5% 对 38.5%）；总 token 有五套落在 −7% 到 +5%。未训练 9B 的 CoReMem 总 token 是 111.7K，对不写记忆的 98.3K，高 14%，落在这五套外面。Mem0、MemOp、ReasoningBank 在它们跑过的六套里，有五套总 token 比 CoReMem 高。

4训练之后还少几步

记忆写出来以后，演员还得决定什么时候按它做。训练组里混着带自己的记忆、不带记忆、带错仓库记忆的会话。成功的会话按 W − 步数 给奖，失败的只给一个小的结局项，于是步数打进成功里。带记忆和不带记忆的平均奖差，当作这条记忆对当前策略的价值。价值只加给门控标成「用了记忆里锚点」的那些步；每一步仍保留结局项。附录 C 写，去掉这笔价值、只留步数奖时，给 27B 一条错仓库记忆会多 2.1 步（区间 [+0.4, +3.9]）；加上之后是 +0.3（区间 [−1.2, +2.1]）。记忆对过测率的好处从 +1.7 个点变成 +2.3 个点。这两格的重放次数和主表不同，27B 完整方法是 6 / 6 / 3。

图 7 的 with-memory 臂重放次数和表 1 不同。只优化过测、不收步数时，27B 这一臂的步从 32.6 降到 30.4，9B 从 91.9 降到 75.5。再把成功里的步数算进奖励，降到 29.7 和 63.8。完整方法停在 29.2 和 72.4。9B 完整方法的步比「记忆加步数奖、不加价值项」高，原文没把 72.4 写成进一步下降。不要把 32.6 和表 1 未训练记忆的 31.8 并成一次下降。

相对「同一份记忆、未训练演员」，训练后再少 24% 步（9B：95.1 → 72.4）和 8% 步（27B：31.8 → 29.2）。这两格也含演员本身变省步的部分。Gemma 只做了 8 次更新，没有按预先规则选检查点。

附录 E 把同一套训练过的演员拿到没有记忆的 SWE-bench Verified 上，500 条、3 次重放。27B 过测 69.2% → 73.7%（+4.5 个点），步 28.3 → 26.2（少 7%）；9B 过测 49.1% → 55.5%（+6.4 个点），步少 22%。未训练行走的是零更新的 LoRA 路径，不是原生基座。换框架看过一次：测试半 96 道下一题里的 94 道，同一 27B 和同一份记忆进 OpenHands，两次重放均值，token 按 raw、含写记忆、不计前缀缓存，不能和表 1 比。不写记忆过测 10.6%、步 33.8；CoReMem 未训练 16.5%、步 38.6；训练后 21.3%、步 45.9。两种 CoReMem 步都高于不写记忆。每百万 token 过测率未训练 13.3、训练后 13.0，对不写记忆的 11.9。ReasoningBank 过测 21.8，高于训练后 CoReMem 的 21.3，步 48.0。不要和 mini-swe-agent 主表的 29.2 对 35.1 并读。

5你的运行位

自己的运行位如果在同一仓库上连续派任务，并且会在上一道结束时写一笔跨任务记忆，这篇预印本测的就是写什么。分段估值只在 27B、linked 边界、把整段轨迹当记忆来做删除。按「下一道未知任务会少走几步」来留，该留的是路径、符号和可再跑的检查；推理、diff 正文、已经消失的 /tmp 草稿，在这套估值里不必留给下一道题。

标题里的 21.0% → 25.7% 是 Qwen3.8-27B-FP8 在 ChainSWE 测试半、mini-swe-agent 上，训练后的 CoReMem 对未训练、不写记忆。17% 步少含训练本身。三套开源权重都训练了；接口三套只跑了未训练记忆。Opus 过测率不变，步从 12.6 到 11.8。Mem0 / MemOp / ReasoningBank 在这六套演员模型上总 token 常常更高，原文没有据此写它们没有记忆效果。OpenHands 上两种 CoReMem 步都高于不写记忆，步数收益没有跟着框架走。

和已有几篇相邻：Agent 记忆由哪些部分组成 讲写、整理、读这三截分工；第一次过测之后还剩 35% 到 60% 的步 讲同一条轨迹里停晚了。这里多出来的是任务边界上的取舍：测试命令和退出码该留给下一道题，推理和 diff 正文不必留给下一道题。

6这篇没测到的

主实验是 Python 仓库、mini-swe-agent。训练只覆盖三套开源权重。别的语言和更大演员，原文写还没测。步和 cache-aware token 当开销，没有墙钟时间和能耗。更长的仓库历史上记忆怎么累积、怎么刷新，原文标成后续工作。代码在匿名链接，本轮没有打开可复核的仓库。

表 1 的百分变化是对「同一演员、不写记忆」。linked 和 unlinked 不要合成一个过测率再去比步。OpenHands 和 SWE-bench Verified 是附录 E，分母分别是 94 道下一题和 500 条实例，和主表 96 道下一题不是同一盘。

Opus 只有 1 次重放。Gemma 和 Luna 3 次。9B 未训练记忆总 token 升高，训练后才降下来。错仓库记忆那两格来自附录 C 的消融重放，不是表 1。OpenHands 上未训练和训练后的 CoReMem 步都高于不写记忆，每百万 token 过测率训练后从 13.3 降到 13.0。
